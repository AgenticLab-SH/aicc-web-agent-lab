# Information architecture
Current top navigation: Accounts / Connections / Automatic switching / Tasks / Tools / Conversations. Shared footer: refresh, Settings and observed status; secondary copy/reconcile actions keep their existing single home. Conversations embeds its own selection and compact message controls in the same tray window.
Accounts: selected-account controls, stable numbered cards, short and long usage/reset times, authentication or transient-error explanation. Login management opens the existing official OCX dashboard and identifies the selected account in tray feedback. Dedicated login-dialog source creation returned blocked by policy; the responsible enforcement layer is unconfirmed. That action was not retried.
Connections: shared health cards, resource footprint and help actions. Automatic switching: existing independent window thresholds/actions. Credits reuse the existing explicit inventory and two-step consumption flow.

## Scroll and density revision
Top: Accounts / Connections / Auto switch and window pin. Accounts: compact comparison list. Fixed selected-account toolbar: Use / Credits / More. More contains pause/resume, priority, automatic selection and official login management. Common footer: refresh, conditional reconciliation, settings, one status line. Copy lives only in settings.

## Glass overview revision
Overview opens by default. Every account shows name, plan, route/status, priority, two quota percentages and reset dates, credit count and nearest expiry. Connection overview and current switch/stop thresholds are always visible. Connections and policy tabs remain for details/editing, not required for basic status. Credits are read-only prefetched sequentially while visible with a five-minute success TTL and ten-minute failure cooldown. Cached credit details render immediately; consumption still requires a fresh verified lookup and explicit confirmation.
## Identity and legibility refinement
Settings: text size (100/110/120 percent), quota presentation (used/remaining). Preferences restore on startup. Tray context menu: status copy and existing open/continuity/exit actions. Tray hover text shows current account and both quota windows; marker indicates known attention or completed connectivity and remains neutral on cached/pending/unknown snapshots. Color alone is never the status contract.
## Warm order workflow
Automatic switching opens with the ordered account list. Select account -> Up/Down -> Save order; draft changes do not contact OCX. Reset restores server observation. Quota rules follow below. Fixed bottom actions use the selected list account and show current use separately; no second account picker on this page. Overview keeps its account picker. Account menu routes order editing to this same page. Current pin behavior is explained beside order feedback.

## Glass and privacy refinement
Overview retains one account selector; its current-use suffix replaces the duplicate caption. Cards combine credit count/expiry into one line. All account presentation uses the shared masking formatter, including clipboard and accessibility. Selection/navigation use visual state without routine success notices. Glass on/off lives in Settings and uses existing local preferences.

## Existing-owner tools implementation - 2026-10-18 KST
- Navigation: Accounts / Connections / Auto switch / Tasks / Tools. Preserve the approved glass surfaces, account masking, font preferences and pin-by-default behavior.
- Accounts and Auto switch: selected account actions expose Use / Pause or Resume / Credit or Automatic selection / More. Pause/resume reuses the existing guarded account action and affects new automatic selection; it does not force-cancel current requests. Remove its hidden menu duplicate.
- Tasks: on-demand read-only summary from the existing continuity helper; show registration title, state, next reset/check time and observation time. Refresh is throttled (10 seconds manual, 60 seconds normal); no background timer, scheduler, duplicate queue or sender. Keep old observations on failure and distinguish helper protocol mismatch. Limit displayed registrations to 24. Existing task management dialog is reused when bundled; otherwise open the existing AICC manager. No enabling/resume/completion is performed by viewing this page.
- Tools: Accounts/rotation -> OCX #codex-auth; request/model/token usage -> #usage; recent failures -> #logs; model/routing -> #models; provider settings -> #providers; installation/version -> local tray release notice and #dashboard. Existing registered management relay is required for these explicit page links. No raw pool-strategy writer or second log/usage store.
- AICC management opens only an already responding loopback local-control owner using the existing CLI host/port convention. It does not invoke the CLI open command that implicitly starts a server. Phone entry uses the existing registered loopback mobile.html page without pairing or creating a listener/tunnel. Diagnostic copy reuses the existing masked current-status copy; it is not a full support bundle.
- Existing Connections retains observed active request counts. A manager's model configuration is not proof of a selected conversation's actual model. Native Codex quota/goal/actions remain in the official Codex owner because no supported installed tray channel is bound. No duplicate Native endpoint, credential read or guessed quota.
- Updates/rollback remain managed maintenance outside this tray scope. Version entry opens the dashboard, not an updater action. Detailed strategy settings and usage/error filtering remain on their owning pages so capability availability follows the installed OCX owner.
- Installation compilation is authorized application work. Automated tests, browser/UI interaction, live control mutations, runtime verification and performance measurement are not part of this change.
## Continuity action guidance · 2026-10-18
Select a conversation, then use **자동재개 켜기**; an unregistered selection is registered in the same workflow. Registration alone remains off. Turning off prevents the next resume and does not interrupt the current turn. **보류 해제** applies only after the displayed hold condition was resolved. **추적 완료** closes continuity tracking without claiming the real task goal is complete. Version mismatch disables registration/enable/resume/complete while allowing read-only refresh and eligible disable. The selected-target panel explains current status and the next available action. Hover, focus, F1 and the clickable guide provide the same core information; essential instructions remain visible.

## Embedded conversations completion · 2026-10-19 KST
- Title filtering stays local. A full UUID/link plus **ID 찾기** or Enter performs one explicit active-history lookup; typing and ordinary refresh never scan the full archive. Protected, archived, ambiguous and missing threads are not rebound or restored. Registered older threads remain visible beyond the 60 recent unregistered candidates.
- Selection identifies the exact message recipient. Text drafts are isolated per selected conversation in memory and survive filtering/navigation while the tray instance remains open. Multiple selection has no shared writable composer. Messages use **보내기 / Ctrl+Enter**; queue acceptance, active response, completed response, interruption and uncertainty have distinct labels. Queued message completion does not imply goal completion.
- Double-click/Enter on one row or **더 보기 → 선택한 대화 열기** opens its exact Codex URI. More also offers masked-context-free receipt metadata and ID copy. Message bodies are not included in copied receipts.
- The existing tray feedback timer only refreshes a visible pending queue, at 15-second intervals with failure backoff. A list refresh builds visible rows once and retains selection. Exact lookup results remain locally available across refreshes.
- Web and phone links use the same existing owner callbacks as Tools. No alternate manager, implicit server launch, pairing operation or public listener is introduced by opening these links.
- Existing-owner feature plan disposition: account use/pause/resume/order/credit/policy, usage/log/model/provider/version owner links, task summaries and registered conversation controls are implemented. Native quota display, unattended OCX target-route admission and external credential-owner adapter replacement retain their separate unsupported/maintenance prerequisites; a successful queue send does not satisfy them.

## One owner behind UI and commands · 2026-10-18 KST
The tray is a presentation/controller client for existing owners. OCX account use/pause/resume/order/policy reuse Invoke-AiccOcxHubAccounts.ps1 and its transaction/evidence guards; account and provider settings open the existing OCX owner. Continuity actions resolve the installed helperPath plus helperSha256 in the existing owner registrations.json on every invocation. The tray-bundled helper is packaging data, not another authoritative manager. Both the summary and auxiliary dialog use the same registered helper and original registry/worker. Agents can use that same installed helper's documented Actions with exact thread/evidence arguments; a Desktop queue registration is not a delivered turn, and unsupported Desktop transport is not substituted with CLI resume. The tray owns only view preferences, layout, masking and local feedback. UI settings are distinct from control-owner configuration.
