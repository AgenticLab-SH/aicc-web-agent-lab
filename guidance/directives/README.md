# AICC 전역 지침 작성 규칙

`fragments/common.md`만 항상 적재되는 정본이다. 이 파일에서 Codex `AGENTS.md`를
생성하며 Claude `CLAUDE.md`는 명시적으로 선택했을 때만 생성한다. `generated/`와
에이전트 홈의 파일은 배포 결과이므로 직접 수정하지 않는다.

지피티=ChatGPT Web 일반 Chat, 코덱스=로컬 Codex CLI와 Desktop. 작업별 스킬·MCP 능력·플러그인 포장/권한·PROJECT 상태·교훈·native 기록은 [공통 계약](../../docs/agent-context-optimization.md#지피티와-코덱스의-공통-계약)을 따른다. 안정 slug/ID를 유지한다. 원격 global/custom/project 지침은 승인된 사용자 소유 exact 대상만 기존 manager로 반영하고 SCREEN·제외 프로젝트는 읽지 않는다.

## 먼저 알맞은 위치를 고른다

| 내용 | 정본 위치 |
| --- | --- |
| 프로젝트와 작업이 바뀌어도 필요한 안정된 행동·보고 경계 | `fragments/common.md` |
| 저장소·하위 폴더의 구조, 명령, 제약, 완료 조건 | 가장 가까운 프로젝트 `AGENTS.md` |
| 여러 세션의 목적·결정·현재/HOLD·다음 행동 | `context/PROJECT.md` |
| 반복되는 판단 절차 | 하나의 focused skill 또는 runbook |
| 입력과 결과가 분명한 반복 절차 | 코드·스크립트와 테스트 |
| 지원 환경의 안정된 화면 절차 | 명시적 권한 아래 녹화 기반 skill |
| 드물고 긴 참고 절차 | cold 문서 |
| 환경값·허용 목록·제품 권한 | config 또는 해당 제품 정책 |

같은 규칙은 한 정본에만 둔다. 다른 문서에는 짧은 설명과 링크만 둔다.

세부 절차는 기존 정본을 사용한다. 공통 지침을 줄일 때 해당 조건을 삭제하거나 새로 복제하지 않는다.

| 내용 | 기존 정본 |

| 실제 로그인 신원과 계정 구분 | [verify-account-identities](../skills/verify-account-identities/SKILL.md) |

내부 임시 배정의 '조사만'·'실행금지'를 전역 규칙으로 만들지 않는다. 사용자가 정한 단계·제외와 구분하고, 승인된 전체 목표에서 다음 구현·적용으로 이어갈 담당과 행동을 남긴다.

## 전역 포함 조건

다음을 모두 만족할 때만 `common.md`에 넣는다.

1. 프로젝트와 작업 종류가 바뀌어도 적용된다.
2. 빠지면 행동·안전·완료 판단·사용자 보고가 실제로 나빠진다.
3. 코드·테스트·권한·config처럼 더 확실한 방법으로 강제할 수 없다.
4. 특정 OS·도구·화면·경로·포트·현재 사건에 묶이지 않고 오래 유지된다.
5. 상위 제품 지침이나 가까운 프로젝트 지침과 겹치지 않는다.

하나라도 아니면 더 가까운 계층으로 내린다. 일회성 조언, 작업 로그, 대화 원문,
비밀·민감정보는 전역 지침에 넣지 않는다.

## 문장 작성 규칙

- 기대 결과와 행동을 먼저 쓰고, 정확한 경로가 필수일 때만 절차를 고정한다.
- 초등학생 비개발자도 이해할 쉬운 말, 짧은 문장, 구체적인 동사를 쓴다.
- 한 항목에는 한 가지 핵심 행동만 두고 같은 뜻은 한 번만 말한다.
- `항상`·`절대`·`반드시`는 안전이나 불변 계약에만 쓴다.
- 수치는 측정값이나 실제 계약일 때만 고정한다. 기본값이면 정확성·안전·사용자 형식이
  우선한다는 예외를 함께 둔다.
- 짧게 쓰더라도 결론·필수 근거·중요 위험·다음 행동은 남긴다.
- 설명·진단과 변경 실행의 권한을 구분한다. 외부 쓰기·파괴·비용·중대한 범위 확대만
  확인하고 안전한 범위의 읽기·수정·검증은 불필요하게 멈추지 않는다.

예시는 제품 요구를 표현하거나 실제 실패를 고칠 때만 둔다. 모델이 이미 아는 일반론,
미사여구, 내부 작업 과정, 여러 표현으로 반복한 금지문은 제거한다.

## 반복 작업은 지침보다 자동화한다

- 두 번째 사용이 생겼거나 재사용 가능성이 크면 먼저 결정적인 단계를 코드·스크립트와
  테스트로 만든다.
- 사람의 판단이 필요한 부분만 focused skill·runbook으로 남기고 입력·출력·성공 조건·검증·
  복구 방법을 명시한다.
- 화면 절차는 환경과 명시적 권한이 지원하고 단계와 성공 기준이 안정적일 때만 녹화 기반
  skill로 만든다. 녹화에는 비밀·민감정보를 넣지 않는다.
- 시간 기반 반복은 별도 자동화·스케줄러가 소유한다. 전역 지침에 일정이나 일회성 작업을
  박아 넣지 않는다.
- 자동화는 원래 요청의 권한을 넓히지 않는다. 외부 변경·결제·삭제 같은 경계는 그대로 둔다.

## 변경·배포 절차

1. 정본·가까운 지침에서 중복·충돌·적합한 위치를 판단하고 자기 변경의 preimage를 보존한다.
2. common.md와 필요한 기존 스킬/참조만 수정한다. 공통 지침에 현재 사건·로그·계정값을 넣지 않는다.
3. 기존 deploy_directives.ps1/deploy_active_skills.ps1에 exact 대상과 스킬을 지정해 생성본/홈에 반영한다. 생성본/홈을 정본으로 직접 수정하거나 prune/optional 범위를 넓히지 않는다.
4. 완료에 필요한 검증은 common.md의 검증 계약을 따른다. 모델 이름만으로 생략하지 않으며 배포기의 파일 복사 응답과 실제 사용 성공을 구분한다.
5. 기존 PROJECT에 변화·배포 응답·남은 적용/호출·다음 담당만 남긴다. 실패는 자기 preimage와 이후 사용자 수정을 구분해 복구하고 전체 dirty를 되돌리지 않는다.

과거 2,048 bytes·12 lines와 측정치는 당시 기준이다. 현재 적재량을 확인하지 않았으면 예산 통과·토큰 절감을 주장하지 않는다. 검사 절차보다 현재 모델 정책이 우선한다.

지속 점검과 최신화는 [정합성 관리 정본](../../docs/agent-context-optimization.md#지속-관리)을 따른다.

## 지피티 자산 자체 관리 연결

스킬·지침·플러그인 생성/수정/삭제는 manage-chatgpt-skills의 asset-lifecycle, Web Project는 manage-chatgpt-assets를 따른다. 두 실행 주체가 같은 내용 주소 백업·기존 AICC 실행기를 사용한다. 새 Web Project의 표시 이름은 w-형식, memory는 default다. 이 작업별 절차를 공통 always-loaded 지침에 다시 복제하지 않는다.
