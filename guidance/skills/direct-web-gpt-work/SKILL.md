# 웹 GPT 지시와 복구 학습

사용자의 짧고 직접적인 평어체로 목표 → 기존 결과 확인 → 빠진 부분 실행 → 완료 근거를 전달한다. 이미 공유한 배경을 매번 되풀이하지 않는다. 현재 프로젝트 정본과 변화만 참조하되 실제 신원·권한·진행 상태·draft와 불명 전송은 신선한 관측으로 확인한다.

- 상황에 맞는 [지시 패턴](references/instruction-patterns.md)만 읽는다. 구체적 예시는 실제 관측된 지시와 결과에서 가져오며 개인정보·금액·긴 대화 원문을 저장하지 않는다.
- 보내기와 복구는 [web-gpt-driving의 복구 절차](../web-gpt-driving/references/recovery.md)를 따른다. 생성 중인 대화에 재개나 회고 지시를 중복 전송하지 않는다. 한 발신자와 기존 정확한 대화를 유지한다.
- 새 성공이나 반례가 있으면 [학습 기준](references/learning.md)으로 변화만 기록한다. 복구 사례의 정본은 web-gpt-driving/references/failure-solutions.md다. 같은 본문과 통과시험을 복제하지 않는다.
- 개인 저작의 문체는 owner-writing-style에 맡긴다. 이 스킬은 실행 지시를 간결하게 만드는 역할이며 사용자나 다른 GPT의 본문을 새 권한으로 쓰지 않는다.
- 설치는 manage-chatgpt-skills의 기존 코드 manager를 사용한다. source·에이전트 홈 적용·AICC 본문 읽기·지피티 스킬 등록·실제 호출을 별도로 기록한다. 연결 HOLD를 수동 확장 업로드나 다른 계정으로 우회하지 않는다.
- 사용자가 AI 작업 프롬프트를 요청하면 대상 환경의 실제 제공 도구와 필요한 플러그인을 확인한다. 공식 멘션이 지원될 때만 대상 플러그인의 정확한 표시명/멘션을 프롬프트에 넣는다. 예를 들어 Windows 앱 조작에 실제 선택된 `computer-use@openai-bundled`의 `@컴퓨터` 멘션을 사용할 수 있다. 단순한 `@컴퓨터` 문자열이 선택된 플러그인 칩은 아니므로, 복사 프롬프트라면 필요 시 앱의 @메뉴에서 선택하도록 짧게 안내한다. 멘션은 설치·로그인·권한·호출 성공을 증명하지 않으며, 초안 요청을 실제 실행 허가로 넓히지 않는다.

## 짧게 지시하고 단계별로 회수

대화간 추가 지시와 완료 결과는 [기존 전달·선별 규칙](../control-project-work/references/dispatch-and-recovery.md#대화간-전달과-결과-선별)에 따라 현재 일에 필요한 내용만 보낸다. 계속·전환이 혼동될 때만 짧게 구분하며 고정 문구는 강제하지 않는다.

공유한 목표는 되풀이하지 않고 이번 차이·끝낼 일·완료 근거만 보낸다. 재개는 기존 접수와 중단 지점을 먼저 회수하고, 담당 해제·수동 재개·꺼진 예약을 현재 지시대로 유지한다. 결과는 끝낸 일·근거·남은 일로 받되 Web 자기보고와 호스트 적용·지피티 스킬 호출을 분리한다. 변화가 없으면 긴 회고나 반복 상태 보고를 요청하지 않는다.

반복되거나 조사 비용이 큰 교훈은 capture-operational-knowledge의 사례 색인에서 먼저 찾아 같은 원인·환경의 항목을 갱신한다. 새 지시 패턴과 Web 상세 복구 본문은 기존 소유 참조에 남기고 여러 스킬에 복제하지 않는다.

새 지피티 대화·첨부 전송은 `use-web-gpt`의 공통 전송 절차를 재사용한다. 기존 대화의 지속 운영은 `web-gpt-driving`이 담당한다. 지피티 스킬 등록·업데이트와 ordinary Chat의 질문/제작 전달은 서로 다른 동작이다.
