# 새 해결이나 반례만 남기기

사례마다 증상 → 실제 관측 → 해결 조건 → 금지할 재시도 → 아직 모르는 점만 남긴다. 원인 추정은 원인 확정과 구분한다. 운영 대화 ID·원본 영수증·민감 내용은 프로젝트 정본에 두고 공통 스킬에 복제하지 않는다.

기존 사례는 web-gpt-driving/references/failure-solutions.md에서 찾는다. 같은 연결·같은 입력·같은 상태의 실패를 새 성공 없이 재시험하거나 이미 통과한 검사를 다시 돌리지 않는다. 새 반례가 생기면 적용 조건을 좁힌다.

- 직접 관측: 현재 응답·링크·전송 접수·새 turn처럼 도구로 확인한 범위.
- 작업자 보고: 파일 존재·해시·문서 수정처럼 작업자가 보고한 범위. 독립 검사 없이는 직접 확인으로 바꾸지 않는다.
- 완료 조건: 내용 정합성·목적지 반영·실제 사용을 해당 요청의 기준에 맞춰 따로 기록한다.

정상 생성 중에는 회고를 요청하지 않는다. 완료·입력 가능 상태와 기존 회고 intent를 확인한 뒤 필요한 질문을 한 번 보낸다. 결과 불명은 재전송하지 않고 기존 결과를 회수한다.

## 단계별 근거와 캐시의 수명

소스·홈 배포는 해당 파일의 반영 근거, AICC 읽기는 반환한 exact skill ID·본문 범위, Web 저장은 불변 ID·파일·preimage와 저장 결과, 지피티 스킬 호출은 그 요청의 실제 load 표시·응답으로 기록한다. 과거 호출은 새 버전 호출의 증거가 아니다. 목적지 반영이 빠졌으면 완료 대신 그 남은 단계를 적는다.

캐시는 동일 대상·근거 시각·소스 SHA/버전·마지막 접수/불명 시도를 보존한다. 새 변화가 없으면 재조사·재시험하지 않고 이전 근거를 재사용했다고 표시한다. 새 사용자 지시·담당 변경·버전 변경·새 실패가 생기면 해당 항목만 다시 판단한다. 신원·권한·전송 직전 상태는 새 행동에 결속한 근거가 필요하다.

모델 선택기 사례의 의미 결속·초기 로딩·한도 구분은 [기존 실패 사례](../../web-gpt-driving/references/failure-solutions.md#모델-선택기의-로딩과-의미-결속-실패)를 참조한다. 소스 수정안·실제 성공 미확인을 유지하고 고정 대기나 index를 일반 해법으로 학습하지 않는다.
