# 필요한 지시만 고르기

재개·고도화·정본 대조·미완료 마무리·핸드오프는 아래 순서로 짧게 작성한다. 긴 설명은 기존 정본을 가리킨다. 작업별 대상과 권한은 별도 확인하며 새 프로젝트나 대화를 임의로 만들지 않는다.

| 상황 | 지시에 담을 것 | 실제 관측과 한계 |
|---|---|---|
| 재개 | 기존 결과와 현재 상태 확인 뒤 중단 지점부터 진행 | `이어서 작업해.` 전송 뒤 새 user turn과 생성 재개를 관측했다. 목표 완료 증거는 아니다. |
| 고도화 | 승인된 목표·새 결함·기존 구현을 바탕으로 빠진 부분만 개선 | 반복 실패 해결과 반례를 정본 참조에 반영하고 기존 배포기로 적용했다. 지피티 스킬 적용과는 별개다. |
| 정본 대조 | 최신 기준일·출처·확정성을 대조하고 차이만 교정 | 이미지 생성 완료 뒤 최신 원장과 다른 내용을 발견했다. 생성 완료만으로 내용 일치를 판단하지 않는다. |
| 미완료 마무리 | 기존 산출물부터 회수하고 목적지 반영까지 남은 단계 명시 | 답변 읽기 실패 뒤 기존 PDF 경로·메타데이터·최종 링크를 회수했다. 중앙 링크 확인과 파일 직접 검사는 구분한다. |
| 핸드오프 | 목표·현재 산출물·미완료·불명 시도·재개 조건·다음 소유자 | 읽을 수 없는 결과나 생성 중 응답을 새 요청으로 대체하지 않는다. 핸드오프 작성 요청·새 대화 이동은 사용자 승인 범위에서만 한다. |

평어체를 꾸미거나 배경을 길게 재설명하지 않는다. 위 표는 지시 구성 패턴이며 모든 문구를 실제 전송된 인용으로 취급하지 않는다. 실제 관측된 단문만 따옴표나 코드로 표시한다.

## 짧은 평어체 예시

아래는 지시 작성 예시이며 실제 전송·성공 인용이 아니다. 현재 승인 범위와 확인된 상태에 맞게 필요한 한 문장만 고른다.

- 재개: 기존 결과부터 보고, 중단된 지점부터 남은 일 이어서 해.
- 미완료 마무리: 이미 된 건 반복하지 말고, 빠진 부분만 실제 목적지에 반영해. 끝낸 일과 근거, 남은 일만 짧게 남겨.
- 변경안 전달: 이번에 바뀐 부분과 적용할 파일만 정리해. 기존 원본과 사용자 수정은 보존해.
- 인계: 현재 담당과 마지막 접수, 불명 시도, 남은 일, 재개 조건을 정본에 남겨. 진행 중인 요청은 다시 보내지 마.

생성 중에는 이 예시를 보내지 않는다. 로그인·권한·전송 결과가 불명인 상태를 문구 변경으로 해결하려 하지 않는다.
