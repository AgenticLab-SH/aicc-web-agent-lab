# Codex 작업 전 비상 복구 확인

목적: Codex가 스스로 연결을 끊을 수 있는 작업을 **시작하기 전에만** 독립적인 복구 수단에 명시적으로 준비를 요청하고, 실제 준비 확인 후 변경한다. 항상 켜진 감시가 아니며 기존 `high-risk-change` 및 원본 보호 지침을 보완한다.

## 적용 판단

- **적용:** 현재 Codex의 모델 경로, `17841` Web GPT, `10100` OCX, 연결된 브라우저/확장·CDP, AICC/Workspace MCP, 인증·설치·업데이트·네트워크·터널·서비스 재시작 등 **실패하면 현재 작업의 실행·복구 경로가 사라질 수 있는 변경**.
- **적용하지 않음:** 단순 문서 작성, 일반 개발·테스트, 조회, 독립 테스트 환경, 현재 작업 경로와 무관한 되돌릴 수 있는 소규모 작업. 불필요한 승인 절차를 추가하지 않는다.
- **우선 원칙:** 시스템·도구 차단, 기존 안전성 검토 결과, 실행 중인 다른 작업의 소유권을 지킨다. 이미 거부된 숨겨진 Web GPT 상시 대기·자동 감시·우회 호출은 실행하지 않는다.

지피티는 ChatGPT Web 일반 Chat, 코덱스는 로컬 Codex CLI·Desktop이다. 지피티 스킬은 지피티에 등록·설치된 작업 절차, 지피티 플러그인은 지피티에서 연결·설치하는 도구·스킬 묶음, 지피티 지침은 사용자 지정 지침과 프로젝트 지침, 지피티 프로젝트는 지피티의 프로젝트 공간, 지피티 대화는 그 안팎의 개별 대화다. 코덱스 스킬은 코덱스가 사용하는 로컬 스킬이다. 코덱스의 일반 작업은 OCX 경로를 사용한다. 네이티브 코덱스는 OCX를 거치지 않는 코덱스이며, OCX·AICC 업그레이드로 OCX 연결이 끊기는 구간의 독립 유지보수·복구에만 사용한다. 작업 범위·독립 복구·복귀 조건을 갖추고, 정비 후 원래 OCX 작업으로 돌아간다. 지피티 자산과 도구 호출은 위 명칭으로 설명하며, 실제 slug·API 키·불변 ID는 유지한다.

## 실행 계약

연결 중단 전 **영향·예상 단절 시간·완료 시각(KST)·복구 방법**을 항상 사용자에게 출력한다. [사전 안내 양식](references/request-and-ack.md#중단-사전-안내)을 따른다.

1. **정확한 대상과 실패 범위 확인.** 유지보수 대상, 현재 연결 경로, 사용자 승인 범위, 실행 중/상태 불명의 요청, 다른 작성자, 위험한 명령, 원상복구 수단을 실제 증거로 확인한다. `UNKNOWN`을 `0`으로 취급하지 않는다.
2. **독립된 구조인지 검증.** 복구 담당자가 변경 대상과 **서로 다른 실행 경로**에 있어야 한다. 예: 변경 대상이 17841이면 17841을 통한 메시지 응답만으로 복구 능력을 인정하지 않는다. RDC 접속 가능 여부와 실제 자동 복구 실행 능력도 구분한다.
3. **허가된 호출 방법 발견.** 현재 도구 목록과 설치된 `--help`/스킬을 확인하고, 본 작업에 대해 **명시적 요청 → 독립 실행 주체의 응답 → 필요한 때 복구 호출**을 지원하는 정식 도구·자동화만 사용한다. 도구 이름·명령·API를 추측해 실행하지 않는다. 일반 Web GPT 단발성 질문은 `READY` 대기 수락으로 간주하지 않는다.
4. **작업 단위로 준비 요청.** 실제 지원하는 도구가 있으면 고유 작업 ID, 1회용 확인 값, 정확한 대상/허용 조치, 담당 복구 경로, 만료 시각, 원본 복구 위치를 전달한다. 이 요청은 항상 사용자 승인 범위 내에서 수행하고 다른 계정·대화로 은밀하게 전송하지 않는다.
5. **READY 확인을 통과해야 진행.** 별개의 담당자로부터 받은 **실제 도구 응답**이 같은 작업 ID·확인 값·대상·범위·만료 전 시간을 가리키고, 복구 경로가 독립적이며, 실행 가능 상태를 읽기 전용으로 재확인해야 한다. 전송 성공, 단순 알림, 상태 조회 성공, 문서의 `READY`라는 단어는 준비 확인이 아니다. 가능한 경우 승인된 작은 무변경 검사를 수행한다.
6. **실패 시 안전 정지.** 호출 수단이 없거나 응답 누락/불일치/만료/사용 중/독립성 미확인/도구 차단이면 위험 작업을 **HOLD**로 두고 관련 없는 안전 작업만 계속한다. 임의의 백그라운드 프로세스·폴링·타 계정·다른 명령으로 제한을 우회하지 않는다. 사람의 개입이 실제로 필요할 때만 정확한 한 행동을 요청한다.
7. **본 작업 및 복귀.** 기존 작업 정보·정확한 되돌리기 지점을 보존한 뒤 승인된 범위만 변경한다. 한 번의 작업 결과가 불확실하면 중복 실행하지 않고 상태부터 대조한다. 성공 후 대상과 비대상 경로의 상태를 확인하고, 단발성 복구 준비를 종료·만료시킨 뒤 기존 작업으로 돌아간다.

## 복구 판단

- 변경 담당 Codex가 응답하지 않는다는 **독립적인 실제 근거** 없이 무조건 재시작하지 않는다.
- 복구 수단이 실제 지원하는 정확한 범위에서만 서비스·세션을 복구한다. 사용자 데이터, 다른 Codex 세션, 브라우저 기존 탭, 계정·권한, 미완료 제출 요청을 보존한다.
- 복구가 필요하면 [요청·응답 기준](references/request-and-ack.md)을 따른다. 실제 transport가 없으면 운영 중인 자동 복구라고 보고하지 않는다.
