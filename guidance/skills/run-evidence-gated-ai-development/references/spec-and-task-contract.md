# 명세와 작업 계약

## 요구사항을 검증 가능하게 바꾸기

- 목적: 누구의 어떤 문제를 왜 해결하는가
- 기능: 입력, 처리, 출력과 정상 흐름
- 경계: 변경할 저장소·폴더·서비스·데이터와 변경하지 않을 대상
- 예외: 빈 값, 실패, 재시도, 동시성, 권한과 복구
- 품질: 성능, 접근성, 유지보수성, 보안과 호환성
- 증거: 어떤 명령·응답·스크린샷·검토가 각 조건을 확인하는가

모호한 형용사를 임의의 취향으로 해석하지 말고 관찰 가능한 조건으로 바꾼다.

## 작업 크기와 병렬화

작업 단위는 한 writer가 독립적으로 변경하고 검증할 수 있어야 한다. 병렬화에는 다음 조건을 모두 요구한다.

- 입력과 출력 계약이 분명하다.
- 소유 파일 또는 책임 영역이 겹치지 않는다.
- 각 결과를 독립적으로 검증할 수 있다.
- 통합 순서와 최종 승인자가 정해져 있다.

기능, 테스트와 문서를 무조건 다른 writer에게 나누지 않는다. 같은 파일이나 같은 설계 결정을 동시에 수정하면 통합 비용이 커진다.

## 예상과 중단 조건

실행 전에 예상 결과와 실패 신호를 적고, 사후 결과에 맞춰 예상 문장을 고치지 않는다.

- 예상: 어떤 값, 상태 또는 오류가 나올 것인가
- 중단: 인증 필요, 운영 데이터 변경, 예상 밖 대량 diff, 반복되는 동일 실패
- 재개: 필요한 사용자 입력, 권한, 외부 상태 또는 새 근거

병렬 실행에는 사용자 또는 적용 지침의 명시적 위임 허용과 각 작업자의 실제 capability가 필요하다. 자동 spawn·새 harness는 기본이 아니며, 검사 책임을 나눠도 상위 정책·도구 권한과 사용자 지정 범위를 지킨다. 완료된 검사는 새 변경·실패·위험 없이 반복하지 않는다.
