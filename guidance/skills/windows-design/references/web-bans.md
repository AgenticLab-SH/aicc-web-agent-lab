# Windows 웹 UI에서 피할 패턴

아래는 기본적으로 재검토할 디자인·동작 안티패턴이다. 제품 요구로 정당화되는 경우 이유와 대안을 기록한다.

- 목록이 핵심인 관리자 화면을 거대한 카드와 중복 버튼만으로 구성하는 것.
- 모든 서비스에 동일한 보라색 그라디언트·글래스 배경·장식용 아이콘을 씌우는 것.
- 마우스에서만 열리는 메뉴, 불명확한 토글 상태, 조작되지 않는 시각 장식 버튼.
- OS 설정·창 레이아웃·브라우저 포커스를 사용자의 직접 동작 없이 변경하는 것.
- 시스템 바로가기와 네이티브 제목 표시줄을 이유 없이 재구현하여 Snap Layouts/키보드 경로를 깨는 것.
- 반투명·테마 변경에서 이벤트와 ContextMenu 등 disposable 객체를 중복 생성하거나 이미 폐기된 UI 컨트롤을 참조하는 것.
- Windows 트레이가 내부 상태 조회를 위해 비싼 브라우저·LLM 프로세스를 계속 상주시켜야 한다고 가정하는 것.
- 장시간 작업 중 무응답, 빈 목록·오류·오프라인 상태를 성공과 동일하게 표시하는 것.

각 예외는 간단한 프로토타입 및 성능·접근성 실측으로만 채택한다.

Web 콘텐츠와 native shell의 책임을 나눈다. tray·파일 대화상자·알림·deep link·단축키·메뉴·창 chrome과 필요한 최소 permission을 명시하고 기존 호스트 구조를 재사용한다. 웹 mockup, 패키징, 설치, 실제 Windows 실행은 각각 별도 상태다. 긴 한국어·좁은 폭·zoom·고대비·keyboard를 설계하며 표의 가로 overflow는 표 안에 가둔다. 현재 Tauri/Electron API는 해당 공식 문서와 host 의존성에 맞춘다.
