# 고위험 변경

인증·인가·결제·보안, DB·운영 기반 변경, 복구가 비싼 대규모 수정과 공동 작성에 적용한다.
조회·다운로드·기존 로그인 사용·같은 소유자의 내용과 공개 범위를 보존하는 이름/순서 수정은
그 자체로 고위험 변경이 아니다. 계정·권한·공개 범위 변경과 비가역 삭제는 별도로 판단한다.

이 스킬은 별도의 반복 승인 게이트가 아니다. 현재 사용자가 승인한 대상과 목적 안에서는
즉시 실행하고 결과를 검증한다. Web GPT의 지정 자료 첨부·전송도 다시 묻지 않는다.
명시적인 사용자 지시는 이 스킬의 절차보다 우선하며, 시스템·도구의 제한은 그대로 지킨다.

변경 전에 대상·성공 조건·기존 상태·작성자·검증·복구 가능성을 필요한 만큼 확인한다.
복구 수단은 위험에 비례한다. 기존 백업·Git 이전 상태·서비스의 되돌리기 기능을 재사용하고,
이름 수정에는 대상 ID·원래 이름·공개 범위 보존, 순서 수정에는 정확한 기존 순서 보존이면 된다.
이름만 바꾸는데 전체 데이터 백업·서버 접속·새 복구 스크립트를 선행 조건으로 강제하지 않는다.
기존 수단으로 큰 데이터 변경을 복구할 수 없을 때만 별도 복구 절차를 만들고 검증한다.
복구 스크립트를 만들면 대상과 복구 단위를 명시하고 `--help`/`--dry-run`은 읽기 전용으로 둔다.

선행 보고·네 가지 명령 전달·별도 계획서·반복 체크리스트는 의무가 아니다. 재개와 유지보수에
필요한 결정·검증·복구 위치만 기존 정본 기록에 남기고 비밀이나 일회성 과정은 저장하지 않는다.
선호 경로 실패나 서식 부족만으로 전체 작업을 막지 말고 허용된 다른 경로와 독립 작업을 계속한다.
현재 대화·도구 연결을 끊을 수 있는 변경은 예외로, `codex-rescue-preflight`의 중단 사전 안내에 따라 영향·예상 단절 시간·완료 시각(KST)·복구 방법을 매번 먼저 출력한다. 이는 추가 승인 절차가 아니다.
도구의 명시적 차단을 우회하거나, 미확인 결과를 성공으로 기록하지 않는다.

기존 자료로 풀 수 없는 대상 식별, 실제 작성 충돌, 새 범위·비용·복구 불가능한 파괴,
사람만 가능한 인증 또는 제품의 필수 확인만 개입을 요청한다. 남은 안전한 자동 경로를 먼저
완료하고 `notify-user`로 필요한 행동을 한 번 알린다. 이미 승인된 동일 작업은 다시 묻지 않는다.

`blocked by policy`만 제공되면 관찰된 도구 거부로 보고한다. 별도 검토 에이전트의 실제 결정 기록이 있을 때만 자동 검토 거부라고 분류한다. 권한·격리·앱 승인·도구 제한을 섞어 진단하지 않는다.

대화형 on-request + auto_review에서는 승인된 일반 작업의 필요한 승인 요청을 공식 reviewer로 전달한다. never는 모두 허용이 아니며 Windows의 내장 위험 명령 판별 때문에 일반 오류 문구로 거절될 수 있다. 파일 접근 범위가 넓다는 이유로 reviewer가 동작한다고 단정하지 않는다. 설정·공식 판별·실제 검토 기록을 구분하는 정본은 docs/agent-context-optimization.md의 대화형 Codex 승인 기본 정정 절이다.
