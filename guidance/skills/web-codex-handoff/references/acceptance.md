# Acceptance matrix: do not inflate statuses

1. **Source prepared**: a valid canonical skill, references and syntax/tests in source; not an installed/live claim.
2. **Skill deployed**: identical SHA-256 at canonical `guidance/skills/web-codex-handoff`, current Codex-recognized `.agents/skills`, optional legacy `.codex/skills` and a relevant activation policy; Codex can discover/read it in a new actual task.
3. **Codex -> WebGPT**: for the Observer/callback path, real dispatch on selected account/surface; exact user/assistant WebGPT turn proof; watch terminal and validated response artifact; one-shot callback to the *originating* idle Codex thread; continued actual Codex next turn; duplicate callback suppressed. For an explicitly requested user-return handoff, accept submission only after the exact saved user turn and actual conversation URL are recorded, the target is preserved and its lease is released; keep the answer `NOT_COLLECTED`. No callback, monitor or resend is required for that mode, and submission does not prove answer completion or continuation of the original task.
4. **WebGPT -> Codex**: dispatch through an actual authorized Codex sender bound to the exact thread UUID and project root; scoped local operation, with tests only when current policy and the request permit them; exact terminal JSON receipt and SHA-256. For return delivery, require the exact completed owned CDP parent watch, approved account/workspace identity, original conversation and user/assistant IDs, task UUID, operation, request ID and private one-shot journal. Use the private `scripts/chatgpt-exact-cdp-followup-cli.mjs` first with `--plan`, then once without `--plan` only when explicitly authorized; require `VERIFIED_DELIVERED` with persisted new user/assistant turn proof in the original conversation. Do not use retired `send-codex-result-to-webgpt.mjs` or historical `POST /api/followups` for live delivery; `QUEUED_NOT_DELIVERED` is queue acceptance only. Missing watch/account/terminal proof remains `AWAITING_DELIVERY`; uncertain delivery requires exact reconciliation, never retry or user tab hijack.
5. **Independence**: originating assistant handles other owned work during wait, without write overlap. No arbitrary tight poll, hidden AI worker, stale replay or account switch.
6. **Workspace deployment**: current AICC Workspace `state=ready`, runtime identity reasons empty, `runtimeReady=true`, command/tool manifest matches deployed code, and one live read plus guarded write canary succeeds without borrowing stale lease.
7. **Noninterference**: 9222-9225, 9336 where applicable, OCX 10100, WebGPT 17841 and other active Codex sessions unchanged except explicit intended scope.
8. **No extra compression**: no new transcript compaction/transport; preserve existing Codex protocol endpoint where needed.

A single link opens a location; **it never proves dispatch or callback**. If any live permission, independent rescue, login, real sender or idle state is missing, mark that acceptance line HOLD with exact blocker/next action. Never mark all-done based on unit tests alone.

## Unrun and uncertain stages

PLANNED, DISPATCHED, TERMINAL, DELIVERY_VERIFIED and ORIGINAL_TASK_CONTINUED each need an exact request/owner receipt. An active or unknown writer, busy target or uncertain result is HOLD; do not replay or substitute another provider. Current policy or missing capability may leave tests and post-checks NOT_RUN. A queued record, result file or link does not advance the originating conversation to a new turn.
