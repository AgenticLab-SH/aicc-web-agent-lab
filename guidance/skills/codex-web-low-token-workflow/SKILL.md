# 지피티와 코덱스 함께 사용하기

전체는 AI 협업 환경, 묶음은 지피티 구성자산·코덱스 구성자산으로 부른다. 지피티는 ChatGPT Web 일반 Chat·extra high 기본(Work 금지), 코덱스는 로컬 CLI·Desktop이다. 구성자산·사용자/환경·제품 운영 진입·기록/보관·동시 작업의 정의는 AICC docs/agent-context-optimization.md의 공통 운영 계약을 따른다. 배포된 홈에 이 문서가 없으면 기존 등록 reader로 필요한 절만 읽고 사본을 추가하지 않는다. 실제 slug·API 필드·불변 ID는 유지한다.
이 스킬이 두 환경의 역할과 경로 선택 정본이다. `use-web-gpt`, `web-codex-handoff`, `aicc-workspace-operator`, `manage-codex-model-routes`는 각각 전송·연결·로컬 도구·경로 변경의 실행 절차를 제공한다. 같은 역할 설명을 별도 스킬로 복제하지 않는다.

여러 프로젝트의 기존 Web GPT 대화를 지속 관제하는 요청은 `web-gpt-driving`으로 연결한다. 반복 확인·큐 처리는 기존 로컬 supervisor와 실행기를 우선하고 모델은 판단과 필요한 복구에 사용한다. 예약 메시지 수신은 작업 실행·OCX 한도 회복·실제 전달 성공의 증거가 아니다.

## 역할 선택

지피티가 실제 제공된 AICC 도구·grant 안에서 구현·적용까지 우선 맡고, 코덱스는 관제·미지원·남은 작업을 잇는다. 도구 부재·권한·실제 실패를 구분하며 답변을 호스트 적용이나 검사 완료로 바꾸지 않는다.

이 단계는 [상세 절차](references/execution-boundaries.md)의 같은 절을 읽고 수행한다.

## 일반 작업은 OCX, 연결 교체는 독립 실행 수단

일반 작업은 현재 OCX 경로를 유지한다. 연결을 끊는 정비만 승인된 독립 실행·복구 수단과 실제 READY·idle·rollback 근거로 진행한다. 계정·provider 자동 우회, UNKNOWN 재발신, 무관한 대화 강제 종료는 하지 않는다.

이 단계는 [상세 절차](references/execution-boundaries.md)의 같은 절을 읽고 수행한다.

## 코덱스 토큰 절약과 지피티 우선 실행

사용자가 말하는 토큰 절약은 코덱스 사용을 줄이고 지피티 일반 Chat+AICC가 가능한 구현·검증·적용을 맡는 것이다. 코덱스는 작은 결과·파일 SHA·검사·설치/실사용 근거를 인수하고 의존성·작성권·미지원 부분을 잇는다. 같은 saved 대화와 완료 산출물을 재사용하고 전체 로그·저장소 재독과 변화 없는 모델 점검을 피한다. 대기·중복 제거·상태 수집은 기존 로컬 실행기를 쓴다. 검증 생략이나 근거 없는 절감률 보고는 하지 않는다.

지피티가 관제하고 지피티가 실행하는 구성은 기존 controller/원장/공식 도구로 단계적으로 검증한다. 현재 노출된 전송·wait·작성권·결과 인수 도구가 모두 있는지 먼저 확인한다. 독립 업무 하나의 배정→실도구 실행→결과 회수→작성권 반환→다음 배정이 실제 성공해야 지원된 범위만 확대한다. 지원 없는 자동 재개를 문안·예약 등록만으로 완료라 하지 않으며 새 daemon·관제 원장·계정은 만들지 않는다.

## 승인·검사·탭 관리

- 맡긴 목적의 기존 사전 승인은 유지한다. 정상 도구 승인·UAC가 나타나면 지정된 절차로 처리하며, 보안 거절을 다른 도구·언어·계정·프롬프트로 우회하지 않는다.
- 완료에 필요한 검증은 공통 지침과 사용자 요청 범위를 따르며 모델 이름만으로 생략하지 않는다. 명시적인 검사 제한과 상위 정책·도구 거절은 위임으로 우회하지 않는다. 미실행은 그대로 기록한다.
- 새 결제, 새 공개 대상, 범위 밖 권한 확대와 복구 어려운 삭제는 기존 승인 범위를 다시 판단한다. 토큰 절감은 권한 확대의 근거가 아니다.
- 브라우저는 같은 계정·workspace의 등록된 슬롯을 lease로 사용한다. 정확한 포트 지시는 그대로 지키고, 선호 포트가 점유되면 다음 등록된 같은 identity만 선택한다.
- 작업 종료 후 소유한 불필요한 target·lease만 반환한다. 사용자 탭, 활성 응답, 소유 불명인 탭과 미완료 재개 지점은 보존한다.

완료는 요청했던 산출물과 실제 반영이 끝난 상태다. 문서·마커·대기열·링크만으로 실제 전송·설치·실행 완료를 주장하지 않는다.
