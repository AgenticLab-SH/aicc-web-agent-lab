# codex-web-low-token-workflow 선택 절차

이 문서에서 선택한 단계만 읽는다. 명령 예제의 기준 작업 폴더와 인라인 리소스 경로는 상위 스킬 루트다. Markdown 링크는 이 파일 위치를 기준으로 한다.

## 작은 왕복으로 실행하기

1. 기존 프로젝트의 목적·정본·현재/HOLD·다음 행동과 Git 상태를 읽는다. 목표와 남은 일을 같은 문서에 계속 갱신한다. 하위 작업도 소유 파일, 원하는 결과, 중지·재개 조건을 유지한다.
2. 로그인된 기존 Web 프로젝트·대화를 우선 재사용한다. `use-web-gpt` 절차로 정확한 계정·workspace·surface·target을 확인한다. 포트 순서로 계정을 추정하지 않는다.
3. Web에 목표, 필요한 소스·구간, 변경 전 SHA, 제약과 짧은 결과 형식을 한 번에 보낸다. 저장소 전체·원본 대화·추론 로그·비밀·프로필을 복제하지 않는다.
4. 독립 조사·분석만 최소 유효 병렬도로 나눈다. 파일과 Git root의 작성 책임은 한 곳에 둔다. Web 직접 구현이 승인되면 해당 소유 범위의 Codex 수정을 멈춘다.
5. Web 결과는 결정, 근거 링크, 변경안, 미확인 사항만 회수한다. base나 파일 hash가 달라졌으면 덮어쓰지 않고 차이를 돌려준다. 불확실한 전송·업로드는 같은 대상에서 확인하고 중복하지 않는다.
6. 실제 Windows 작업은 Workspace 도구나 현재 턴에 정확히 바인딩된 Codex 도구로 실행한다. Web 컨테이너의 파일 수정은 Windows 적용이 아니다. 연동은 `web-codex-handoff`와 `aicc-workspace-operator`를 따른다.
7. 소스 변경, 사용자가 요청한 검사, 실제 설치·실행, commit/push와 Notion 읽기 결과를 구분한다. 한 단계가 막히면 원인·재개 조건·다음 담당을 정본에 남긴다.

## 일반 Chat와 스킬 사용

일반 Chat만 사용한다. 현재 같은 모델·계정의 실제 선택지에서 xhigh(Extra High)를 우선하고, 없을 때만 high를 쓴다. Max·Ultra·Pro로 대신하지 않는다. 자기 소유 작업 화면의 Chat/Work 선택을 확인하고 Work면 Chat으로 바꾼다. Work에서는 입력·첨부·전송·도구 호출을 하지 않는다. 스킬 버튼이 Work로 이동하면 일반 Chat의 지원 경로를 사용한다. 한도·모델 잠금을 Work 전환·다른 계정·결제로 우회하지 않는다.
지피티 스킬은 일반 Chat의 실제 로드 표시와 요청·완료 응답으로 각각 확인한다. 목록·설치·이름 언급은 호출 증거가 아니다. AICC 플러그인의 skill_inventory/skill_read로 본문을 읽어 활용하는 경로도 사용할 수 있지만 이를 지피티 스킬 로드로 보고하지 않는다. 일반 Chat에서 기능이 없으면 그 현재 범위만 보고하며 전체 제품의 미지원으로 단정하지 않는다.
공용 Business 워크스페이스의 AICC 연결은 승인된 구성원들이 공유하는 기존 연결을 재사용한다. 계정마다 새 Tunnel·플러그인·키를 만들거나 개인용 게시를 공용 연결 사용의 선행 조건으로 요구하지 않는다. 별도 Personal 연결은 사용자가 그 용도를 요청한 작업에서만 다룬다.

## Web에서 끝낼 일과 호스트가 필요한 단계

현재 Web에 제공된 검색·연결 앱·분석·문서·이미지·프런트엔드 산출물 기능으로 끝낼 수 있는 단계는 그 대화에서 직접 완료한다. Windows 원본 저장소·서비스·설치본에 실제 손을 대는 단계만 승인된 호스트 도구를 쓴다. 호스트 도구가 작업을 직접 처리할 수 있으면 자료 조회나 전달 확인을 위해 Codex 모델을 별도로 깨우지 않는다. Web 산출물과 Windows 적용은 따로 기록하며 현재 Codex 작업의 OCX 경로 기준은 유지한다.

## 변화만 읽고 근거까지 넘기기

- 정본에는 목표·현재 담당·마지막 산출물·미완료·HOLD·다음 행동만 유지한다. 이어받을 때 그 요약과 바뀐 파일·마지막 결과를 먼저 읽고, 결정을 바꿀 때만 필요한 원문 구간을 연다.
- 캐시는 exact 대상·근거 시각·소스 버전 또는 SHA·마지막 접수와 불명 시도를 결속한다. 버전이나 상태가 바뀌면 해당 항목만 갱신한다. 로그인 신원·전송 직전 draft/생성·권한·불명 시도는 오래된 캐시로 통과시키지 않는다.
- Web에는 목표와 새 차이, 필요한 파일/참조 위치, 끝났다고 볼 근거를 짧게 전달한다. 읽기만 필요한 일은 기존 호스트 도구로 처리하고 모델 왕복과 대화 전체 재주입을 늘리지 않는다.
- 담당 해제·예약 중지는 다음 회차에도 유지한다. 수동 재개 지시는 현재 맡긴 기존 일에만 적용하며 새 예약·감독기·자동발신을 켜는 근거로 삼지 않는다.
- 결과에는 원했던 일·끝낸 일·남은 일과 실제 근거를 적는다. 소스 작성·홈 배포·AICC 본문 읽기·Web 저장·실제 지피티 스킬 호출을 각각 표시하고, 구현·서버 적용·사용자 사용 완료를 서로 대신하지 않는다.

반복 장애나 큰 조사 비용을 줄일 교훈은 capture-operational-knowledge의 작은 색인에서 관련 사례1~2개만 읽고 기존 항목을 갱신한다. 현재 미해결은 프로젝트 정본에 남기며 성공 한 번·설치·UI 생성 표시를 실제 진척이나 전체 해결로 확대하지 않는다.

## 관리 변경의 전파

스킬 변경은 source 해시와 짧은 영향도 판단을 기존 manager의 변경 동기화 계약에 연결한다. 공통 절차·환경별 적응·로컬 전용을 구별하고 불변 파일은 재전송하지 않는다. 캐시는 변경 감지용이며 실제 로그인·권한·불명 전송의 조정을 대체하지 않는다. 지피티 프로젝트 표시명은 `w-`, 코덱스는 `l-`을 사용하며 경로와 ID는 보존한다.

## 화면 사용 한도 안내

이 환경의 workspace 사용 한도 배너는 Codex 사용량 안내이며 일반 Chat 작업을 막는 조건으로 쓰지 않는다. 기존 OCX의 계정 전환·소진 전 차단을 유지하고 승인된 작업을 이어간다. 실제 요청 거절·OCX 차단과 MCP 429는 [공통 운영 기준](../../manage-chatgpt-skills/references/quota-and-connection.md)으로 분리한다. 사용자가 xhigh 유지를 명시한 작업에서는 high로 낮추지 않는다.
