# 기한까지 작업 이어가기

사용자가 맡긴 목표·단계 순서 안에서 실제 다음 일을 수행한다. 기한은 새 작업을 시작할 수 있는 상한이며, 할 일을 꾸며 시간을 채우거나 미완료를 완료로 바꾸는 기준이 아니다. 기존 `control-project-work`의 원장·writer·전송 계약을 재사용한다. 이 스킬은 별도 스케줄러나 새 관제 원장을 만들지 않는다.

## 처음 적용할 때

- 현재 시각과 명시한 기한을 KST 및 UTC offset으로 고정한다. 기존 기한이 살아 있으면 재질문하지 않는다. 새 기한을 임의로 연장하지 않는다. 기한이 없으면 시간 제한 없는 승인 업무로 유지하며 종료 시각을 만들어내지 않는다.
- 기존 PROJECT와 작업 state에 exact 대화·root·단계·성공 기준·취소 상태·단일 발신자·마지막 실제 산출물을 연결한다. 현재 단계의 미완료 산출물을 `실행 가능 / 의존 대기 / 실제 외부 차단 / 미조사`로 나눈다. 긴 재고 조사 대신 다음 결정을 바꿀 부분만 읽는다.
- 트레이 추적 목표·현재 대화 큐·Codex 내장 goal의 기존 상태를 먼저 읽는다. goal 사용이 사용자 요청에 포함됐으면 현재 goal을 재사용하고, 없을 때만 승인된 목적·기한·중지 조건으로 생성한다. 다른 목표가 있으면 덮어쓰지 않는다. [AICC 연결 계약](references/aicc-goal-queue.md)을 따른다.
- 사용자의 기존 예약 취소와 새로 요청한 큐 사용을 구분한다. 큐를 켠다고 반복 예약을 되살리지 않는다. 자기 자신에게 후속 메시지를 보내 지속 작업을 흉내 내지 않는다.

## 실행·복구·종료

실제 다음 동작을 고르거나 병렬 배정·HOLD·한도 복구·기한 변경·종료를 판단할 때 [실행 수명주기](references/run-lifecycle.md)의 해당 절을 먼저 읽는다. 단일 writer와 기존 원장·UNKNOWN을 보존하고, 전체 목표가 남았으면 미완료를 완료로 바꾸지 않는다. 한도 예정 시각이나 큐 등록은 실제 복귀가 아니다.
