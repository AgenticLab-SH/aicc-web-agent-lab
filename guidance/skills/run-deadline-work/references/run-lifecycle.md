# 실행·복구·종료 상세

## 병렬 개발과 지정 모델

사용자가 병렬 개발을 승인하면 현재 실제 동시 실행 슬롯과 독립 파일·데이터·배포 효과 범위까지 작업을 나눈다. 단계 제한을 바꾸는 최신 직접 지시는 기존 순서보다 우선 반영하고, 허용한 그룹 외로 넓히지 않는다. 완료된 검사를 나눠 반복하는 것을 병렬 개발로 세지 않는다.

새 작업자는 사용자가 지정한 모델·추론 수준을 명시해 생성한다. Fast 금지는 보존한다. 모델을 바꿀 수 없는 기존 작업자는 안전 경계에서 작성권을 반환받고 새 작업자로 인계한다. 시작 전 실제 쓰기 상태·파일 소유권·불명을 보존하며 진행 중 mutation을 겹쳐 재배정하지 않는다. 전달이 누락됐으면 같은 작업자에게 평문 범위만 보충하고 별도 작업을 중복 생성하지 않는다.

각 작업자에는 원래 미완료 요구, 정확 root/파일 소유권, 기존 결과, 산출물, 기한, 제외와 현재 검증 정책을 준다. dirty 문서·상태를 갱신하는 작업자에게는 쓰기 전 정확 원문 preimage를 기존 작업 복구 폴더에 보존하도록 전달한다. JSON은 exact ID의 단일 객체를 수정하며 전역 정규식으로 next/시각/증거를 치환하지 않는다. 소유 ID가 없거나 중복이면 원본을 쓰지 않는다. 문서 갱신 오류는 해당 파일만 중지·보존·복구하고 독립 제품 구현을 멈추지 않는다. 메인은 중앙 상태와 통합을 소유한다. root 전체를 여러 writer에게 동시에 주지 않는다. 같은 root를 나누려면 파일·공유 원장·데이터·배포 영향의 비겹침을 확정하거나 별도 worktree를 사용한다. 인수 전 기존 writer 반환을 확인하고 타 변경을 되돌리지 않는다.

슬롯이 모두 사용 중이면 같은 일을 다시 배정하지 않는다. 먼저 반환된 결과를 채택하고 빈 슬롯에 다음 독립 미완료를 맡긴다. 한도 리셋 예정 안내만으로 이미 실행 가능한 작업을 멈추거나 회복을 선언하지 않는다.
사용자가 실제 한도 초기화 전 병렬·초기화 후 순차를 지정한 run에서는, 동일한 실제 계정의 공식 fresh 사용량에서 초기화 전후 변화를 관측하거나 사용자의 초기화 통지를 받아야 전환한다. 다른 계정의 0%, 예정 시각 경과, 일반 응답 성공만으로 초기화를 확인하지 않는다. 확인 전에는 승인된 독립 작업을 병렬 배정하고, 확인 후에는 신규 병렬 배정을 멈춘 뒤 이미 접수된 원작업을 모두 회수하고 순차 지시한다. 계정 대응·관측 시각·전환 근거와 원접수 잔여를 기존 현재 상태에 기록하며, 초기화 확인을 기다린다는 이유로 실행 가능한 독립 업무를 멈추지 않는다.
## 실행 중 판단

매 새 실행 회차의 첫 동작으로 clock을 확인한다. 기한 전이면 원래 승인된 미완료 산출물에서 다음 구체 동작을 선택한다. 이미 활성 writer나 접수·불명 전송이 있으면 원 결과부터 회수하고 중복 배정하지 않는다. 한 root 한 writer와 원격 단일 sender를 유지한다.

일반 파일 읽기의 `AccessDenied`·`EPERM`이나 제한된 실행 계정 오류를 실제 보안 거절과 구분한다. 기존 사용자 승인과 등록 관리자 실행 범위에 속하는 정확한 명령은 제공되는 `require_escalated`·정식 자동 검토 경로에 제출한다. 성공하면 같은 원동작을 잇고, 실제 검토·도구·보안 거절이 있으면 중지해 오류와 범위를 보존한다. 다른 도구·계정·인코딩으로 거절을 우회하지 않는다. 단순 권한 부족을 영구 차단으로 확대하지 않는다.

설치본과 현재 소스의 불일치는 출처를 확인할 질문이다. 과거 설치 산출물과 byte 동일한 전체 소스가 없으면 기존 복구본·변경별 원담당·승인 범위로 현재 통합 후보의 포함 여부를 판단한다. 미완료/출처 불명 변경을 무단 포함하지 않되, 옛 byte 동일성만을 모든 향후 릴리스의 영구 조건으로 만들지 않는다.
`미조사`는 메인의 조사·판단 업무다. 다음 일을 아직 못 찾았다는 이유, 하위 작업자 반환, 파일 수정시각 불변, 완료된 검사의 재실행 금지, 한 묶음의 설치 차단은 전체 대기 근거가 아니다. 실패한 가지의 오류와 해제 조건을 보존한 뒤 독립 가지를 수행한다. 실제 보안 거절은 다른 수단으로 재시도하지 않는다.

현재 기록에는 다음을 결속한다. 기존 필드를 사용하고 대화마다 새 작업표를 만들지 않는다.

- 다음 동작의 원래 요구·대상 파일/API·owner·의존성·예상 산출물.
- 실행 결과가 바꾼 현재 상태와 마지막 실제 산출물 시각.
- 실패하면 정확 원동작·오류·부분 실행/접수 여부와 다음 유효 방법.
- 다음 구체 동작. 결정이 안 됐으면 미조사 담당과 조사 질문을 남긴다.

도구 호출 수·파일 timestamp·goal ACTIVE·WATCHING·큐 켜짐은 산출물 진전이 아니다. 진전 없는 실행이 반복되면 같은 조회를 계속하지 말고 가정을 바꾸거나 미조사 요구를 분해한다. 승인된 연속 작업 전체가 정체했는데 실행할 다음 행동이 없으면 마지막 실제 산출물과 원인·미조사 잔여·책임을 한 번 명확히 알린다. 정상 진행이나 같은 외부 대기 상태를 반복 보고하지 않는다.

## 전체 대기를 결정할 때

현재 단계의 모든 미완료 산출물이 관측된 오류·의존성·해제 사건·담당과 연결되어 있고 미조사 항목이 없을 때만 전체 외부 대기를 판단한다. 큰 항목의 한 가지 차단을 그 안의 모든 요구에 전파하지 않는다. 기존 도구로 가능한 독립 구현·적용·운영 업무가 남았는지 해당 요구 수준에서 판단한다. 새 요구나 중단 제품을 만들어 실행하지 않는다.

AICC 추적 상태는 실제 사실만 반영한다. 내장 goal의 blocked/paused/complete는 제공 도구의 상태 변경 조건을 따른다. 한 번 막혔다고 즉시 blocked로 바꾸거나, 임의로 paused를 써서 지속 작업을 끝내지 않는다. 기술적으로 지속 실행 수단이 없으면 그 범위를 알리고 원 큐·checkpoint를 보존한다.

## 한도와 연결 복구

실제 요청 거절과 화면상의 한도 안내를 구분한다. 실제 quota 실패의 원동작·오류·대상 경로·resetAt·cursor를 기존 state에 보존한다. 같은 OCX 경로의 fresh quota/admission과 원 ACK·새 turn·결과부터 조정한다. reset 시각 경과는 회복 증거가 아니다. 새 계정·모델·Native 대체·서비스 재시작으로 복구했다고 하지 않는다. 호스트가 실행되지 않거나 지원 sender가 없으면 스킬·큐 등록만으로 자동복귀를 보장하지 않는다.

## 중요한 변경의 한시적 복구 확인

사용자가 독립 복구 대화와 지연 확인을 명시했으면 `codex-rescue-preflight`의 현재 지원 경로를 재사용한다. 대상 프로젝트/대화, operation ID, 허용 조치, 복구 위치, 시작·만료, 단일 발신자를 결속한다. 지연 시간은 예상 교체와 복귀 시간을 감안해 메인이 정하며, 실제 정상 복귀 근거가 들어오면 이번 operation의 확인만 취소한다. 이 사용자 요청은 해당 변경에 한정된 단회 지연 확인의 근거이며 상시 감시·다른 대화 자동 발신 권한이 아니다. 대화 생성·접수, 프로그램 준비·기동, 독립 READY, 실제 복구·원업무 재개를 분리한다. 지원 전송 기능이 없으면 그 기능을 승인 범위에서 마련하는 개발을 다음 작업으로 두고, 등록만으로 동작을 보장하지 않는다.

내장 goal의 모델 도구에 재개 기능이 없으면 먼저 현재 exact 대화의 공식 TUI `/goal resume` 지원을 확인한다. 사용자가 재개를 요청했고 해당 터미널을 확인할 수 있으면 [터미널 직접 재개](aicc-goal-queue.md#현재-터미널에서-직접-재개)를 수행하고 실제 상태를 읽는다. 터미널과 공식 API 모두 사용할 수 없을 때만 그 한계를 기록하고 독립 업무를 계속한다. 미완료 goal을 완료로 바꿔 새 goal을 만들거나 내부 저장소를 직접 고치지 않는다.
## 기한·취소·완료

기한 도달 후 새 배정·발신·설치를 시작하지 않는다. 진행 중 작업의 안전 checkpoint와 미완료·반환 owner를 보존하고 이 run의 현재 대화 큐만 기존 Disable로 끈다. 강제 kill·다른 대화 변경·전체 목표 완료/보관 처리는 하지 않는다. 사용자 취소도 취소한 범위만 반영한다.

시간제 관제 run 종료와 제품 전체 완료를 분리한다. 내장 goal의 목적이 이 시간제 run이면 종료 조건을 실제 충족했을 때만 complete로 표시하고, 전체 개발이 목적이면 미완료를 완료 처리하지 않는다. 계속하는 기한이나 예약은 사용자 지시 없이 만들지 않는다.

완료 검증은 공통 지침과 사용자가 명시한 범위에 맞춰 수행한다. 모델 이름만으로 생략하지 않으며 에이전트·도구에도 같은 권한 경계를 적용한다. 스킬 설치·절차 적용·큐 선택·실제 전달·기한 종료·실 quota 복귀를 따로 보고한다.

## 승인 검토 장애와 계속할 수 있는 작업

`Automatic approval review failed`는 해당 요청의 검토가 완료되지 않아 작업이 실행되지 않은 상태다. 위험 판정 거절, OS 파일 접근 거절, 모델의 실제 quota 거절과 따로 기록한다. 실패한 검토를 사용자 포괄 승인이나 남은 계정 한도로 덮어쓰지 않는다.

차단 범위는 원동작별로 판단한다. 운영 교체·보호 파일 쓰기·다른 대화 발신이 검토 장애로 실행되지 않았어도 기존 권한으로 가능한 읽기와 별개 일반 소스 작업까지 실패했다고 가정하지 않는다. 반대로 실패한 동일 동작을 다른 도구·계정·셸·임시 파일·Native 경로로 옮겨 검토를 건너뛰지 않는다. source 작성, 운영 설치, 원 작업 재개는 별도 결과다.

기존 원장의 미완료 요구에서 다음 구체 동작을 고른다. 일반 소스 작업도 실제로 거절되면 그 경계를 보존한다. 단순 접근 실패는 기존 정식 권한 경로에 제출할 수 있지만 실제 검토·보안 거절 뒤 권한 guard를 바꾸지 않는다. 실행하지 않은 계획과 상태 보고를 진전으로 세지 않는다.

주 작업 모델의 응답 성공은 승인 검토 모델의 정상 동작을 증명하지 않는다. 계정 사용량, 공개 모델 catalog, 숨겨진 control-plane 모델 지원, 기존 대화의 issuer 귀속을 구별한다. 원 실패와 상관된 안전한 code/phase/dispatchStarted만 사용하며 인증·요청 본문·계정 비밀은 기록하지 않는다. 검토 모델을 일반 모델로 치환하거나 검토 기능을 끄는 방법은 복구가 아니다.

독립 정비가 필요하면 기존 승인 범위·소유권·정식 검토를 유지한 정확한 인계 프롬프트를 남긴다. 복구 대화 생성, 메시지 접수, 실제 담당 시작, fresh 독립 READY와 원 대화 재개를 각각 관측한다. 지연 프로그램이 이미 한 번 전송하고 종료했다면 이를 취소 성공으로 바꾸거나 같은 요청을 다시 보내지 않는다.

## 중간 지시와 기한 갱신

사용자가 새 종료 시각을 확정하면 이전 날짜별 이력은 보존하고 기존 실행 상태와 연결된 목표의 현재 기한 필드만 갱신한다. 문서 전역 치환이나 내장 goal 저장소 직접 수정은 하지 않는다. 내장 goal과 AICC 추적 목표 중 한 곳만 바뀌었으면 두 곳 모두 적용됐다고 하지 않는다. 과거 실행 폴더 이름에 옛 시각이 있어도 실제 실행 시각으로 해석하지 않는다.

새 메시지·다른 대화의 결과는 원래 목표에 누적한다. 직접 취소나 양립할 수 없는 지시가 없으면 진행 중 구현을 버리지 않는다. 관제 보고에서는 어떤 제품의 어떤 산출물이 실제로 바뀌었는지, 아직 적용되지 않은 부분과 다음 담당을 짧게 밝힌다.
