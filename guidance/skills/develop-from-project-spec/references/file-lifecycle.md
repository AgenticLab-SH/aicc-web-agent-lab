# 문서와 파일 수명주기

개발 준비·인계·마감에서 필요한 범위만 사용한다. 파일을 정리한다는 이유로 제품 기능·서비스·사용자 자료를 지우지 않는다.

## 새 파일을 쓰기 전

기존 정본/등록 경로를 찾고 파일의 역할을 정한다: source·현재 문서·파생 보기·개인 자료·실행근거·캐시·백업. 같은 역할의 파일이 있으면 갱신한다. 비슷한 이름만으로 같은 자료라고 보지 않는다.

- 코드/제품 문서는 해당 제품의 기존 Git/root. 전역 정책·스킬은 guidance 정본, 홈/플러그인 전달본은 기존 배포기.
- 원본·로그인·작업 DB·session·lease·attempt·백업은 해당 owner/runtime에 둔다. 코드 저장소의 docs나 지피티 컨테이너에 복제하지 않는다.
- 경로/실행기는 기존 등록/locator/config를 사용한다. 개인 PC 절대경로·포트·계정을 재사용 스킬이나 공개 source에 박지 않는다.
- 임시자료는 기존 staging/cache 아래 작업 식별이 가능한 범위에만 만든다. 비밀·원문 대화·capability는 장기 기록과 원격 백업에서 제외한다.

## 기록은 사건이 있을 때

착수·의미 있는 결정·외부 효과/실패·인계·마감 때 current와 필요한 spec/task만 갱신한다. 도구 호출마다 보고서·새 날짜 파일·고정 주기 로그를 만들지 않는다. 같은 내용은 링크하고 변경분만 읽는다. 캐시는 원문의 revision/hash·범위·생성 시각을 붙여 재사용하되 신원·권한·현재 초안/생성·불명 전송을 대신하지 않는다.

완료 후 제품 계약·계속 유효한 결정·필요 복구/근거만 현재 입구에 남긴다. 끝난 임시 plan/task는 중요한 결정·남은 항목을 정본에 인수한 뒤 Git 이력/기존 cold 보관으로 내린다. 활성 파일명에서 후계자를 가리킬 짧은 링크가 필요하면 남긴다. 지나간 기한·담당을 현재 명령처럼 부활시키지 않는다.

## 합치거나 없앨 때

선택 파일만 기존 위치→후계자→고유 내용→참조/consumer→처분을 대조한다. 거대한 새 정리 원장을 만들지 않고 기존 목록/작업의 작은 표에 쓴다.

- **중복 문서:** 현재 정본에 고유 요구/결정 인수, 입구·링크 갱신 후 불필요 사본만 정리.
- **파생 HTML/export/cache:** 생산자·입력·현재 후계자/재생성법·필요한 소비자를 확인. 고정 산출물을 교체하며 자동 legacy/final 사본 누적을 피한다.
- **개인 자료/제품 퇴역:** source·실행환경·사용자자료·외부참조를 별도로 판단. origin DB는 코드 이동으로 이전되지 않으므로 필요한 export/import·수동 편집·복구를 지킨다.
- **백업:** 복구에 필요한 세대·사용 중 버전·불명 attempt를 보존. 기존 내용 hash가 같으면 재사용하며 변경 때마다 무기한 중복 ZIP을 만들지 않는다. 보존 기한은 실제 자료·복구 요구로 정하고 근거 없는 전역 N일 삭제는 만들지 않는다.
- **삭제:** 승인 범위·정확 경로·파일 정체·고유 자료/활성 작업·복구 요구를 확인한 선택 대상만. dirty/미추적/unknown·원본 유일본은 자동 삭제 대상으로 삼지 않는다. Windows는 PowerShell LiteralPath와 링크 경계를 따른다. 거절된 삭제를 다른 언어/명령으로 우회하지 않는다.

하드코딩 경로 교정은 실제 producer/config/consumer가 확인된 범위에서 한다. 무작정 전체 치환이나 홈/서버/로그인 이동은 하지 않는다. 전체 src나 Codex 홈을 정리 대상으로 잡지 않는다.

## Notion·GitHub·지피티 전달

- Notion은 기획/결정/링크의 기존 exact 목적지만 갱신한다. 개발 source·현재·실행근거의 정본을 역할 없이 이중화하지 않는다.
- GitHub commit은 선택 파일/의미 단위로, push는 현재 사용자 승인·원격 공개 범위에 맞춰 수행한다. 새 비용·공개 대상·비밀/개인 자료는 별도 판단한다.
- 스킬·지침·플러그인 백업/배포는 manage-chatgpt-skills의 자산 수명주기와 기존 manager를 따른다. 이 일반 문서 정리가 이중 백업이나 원격 재게시의 대체 절차가 아니다.
- 코덱스는 호스트 파일/dirty/담당을 읽고, 지피티는 AICC가 노출한 등록 root와 현재 도구 권한 안에서 같은 규칙을 적용한다. 경로가 보인다는 이유로 쓰기 가능을 가정하지 않는다.

## CI와 예약 실행

- 워크플로의 실제 목적·트리거·소유자·작업 수·러너와 필수 체크를 먼저 파악한다. push가 저장만 하는지 검사·배포까지 시작하는지 구분하며, 실패한 검사도 실행 비용을 쓴다.
- 복구용 데이터만 변경되는 전용 경로는 코드 CI의 push/PR 대상에서 제외한다. 제품 코드도 함께 바뀌면 검사하고, 필수 체크 때문에 경로 제외가 merge를 막는 경우에는 성공 상태를 남기는 job 조건으로 분리한다. 비밀 탐지처럼 문서에도 필요한 검사는 유지한다.
- 같은 브랜치의 오래된 CI는 concurrency로 취소하되 배포·릴리스의 중간 취소는 별도로 판단한다. 반복 OS/버전 행렬은 실제 지원 범위에 맞추고, 변경 없는 전체 검사를 예약하는 대신 목적에 맞는 변경 기반 검사·정기 점검을 고른다.
- 예약 실행은 외부 데이터 갱신·배포·보고 등 사용자 효과가 있을 때 유지한다. 사용자 승인으로 퇴역한 검사는 명시적으로 중지하고, 성공 결론만으로 skip된 업로드·배포를 완료라 하지 않는다.
- 백업은 내용 해시로 재사용한다. CI 회피용 표시를 제품 코드 커밋에 일괄 붙이거나 보안 검사를 꺼서 실패를 숨기지 않는다. 사용량 제한 정비 자체에서 허용되지 않은 사후 CI를 새로 시작하지 않는다.
## 짧은 마감

정리한 역할·처분·후계자·다음 행동만 보고한다. 파일 수/절감률을 측정하지 않았다면 주장하지 않는다. 문서 작성, 파일 이동/삭제, 홈 배포, 원격 설치, 실제 호출을 구분한다. 정리하지 못한 원인은 해당 항목에만 남기고 독립 준비를 계속한다.
