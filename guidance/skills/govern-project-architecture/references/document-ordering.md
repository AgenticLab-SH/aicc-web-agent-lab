# 프로젝트·경로별 문서 정렬과 반복 방지

## 정본 선택

사용자가 지정한 기존 문서 표준을 우선한다. 없으면 workspace 지도에서
Project Control의 DOCUMENT_STANDARD 같은 기존 표준을 찾는다. 새 범용 체계나 모든 프로젝트의
current를 복제한 표를 만들지 않는다. 기존 표준이 없을 때만 현재 프로젝트 index에 최소 기준을 둔다.

## 정렬 순서

기존 README/index를 진입→현재→계획·계약→실행·운영→근거·지식→보관 순서로 연결한다.
파일명 번호·폴더 구조를 일괄 변경하지 않는다. 같은 역할을 하는 기존 파일은 이름이 달라도 재사용한다.
공용 source/개인 state/설치판/runtime/서버·외부 문서/지식 볼트/evidence/backup을 구분한다.
자동 생성본은 source가 아니며 Notion 우선순위·Git source·runtime 관측은 각 owner에 남긴다.

## 한 batch의 실행

1. 기존 지도·등록부로 대상과 canonical path/Git root를 정한다. 별칭은 중복 집계하지 않는다.
   홈/디스크 전체를 재귀 탐색하지 않는다. 미등록·미접근 경로는 다음 편입 대상으로 기록한다.
2. 해당 current·dirty·active writer와 원본을 확인한다. 읽기 감사와 쓰기 범위를 분리한다.
   보호영역·진행 writer·미결 UNKNOWN은 보존하며 제외를 전체 검사 PASS로 바꾸지 않는다.
3. 같은 작업 ID와 완료 근거를 재사용한다. current의 바뀐 항목만 갱신하고
   source/설치/실행/실사용·HOLD 조건·다음 owner를 구분한다.
4. 중복 내용은 유지/통합/보관/보류로 판정한다. 고유 내용·출처·과거 일자·원본 근거를 보존한다.
   이동 전 역참조와 consumer·복구점을 확인한다. 새 index/링크만으로 충분하면 이동하지 않는다.
5. 변경한 링크·내용 보존·해당 배포 결과만 확인한다. 새 변경·위험이 없으면 통과 검사를 반복하지 않는다.
6. 기존 execution/current에 대상·이번 차이·근거·제외·남음과 다음 batch를 반영한다.
   문서 표준 작성/스킬 설치/개별 batch/전체 정리는 각각 별도 완료다.

## 적용 경계

- 전 프로젝트 정렬 요청: 기존 중앙에 G-DOC 같은 독립 그룹을 등록하되 기능 우선순위를 보존한다.
- 단일 프로젝트 정합화: 해당 README와 current만 갱신하고 중앙 중복 작업표를 만들지 않는다.
- README 오타, 코드 한 줄 설명: 일반 수정으로 끝낸다.
- 운영 값/계정/서비스·서버 변경: 문서 정리로 실행하지 않고 원 owner의 기존 계약으로 넘긴다.

기존 감사기를 사용한다면 실제 지원 scope와 제외·link/junction 처리를 먼저 확인한다.
실행 실패·누락·깊이 제한은 NOT_VERIFIED로 기록하며 자동 수정이나 전체 완료로 승격하지 않는다.
