# General Report Design

상태: `confirmed default`
버전: `1.0.0`
성격: 브랜드 중립, 근거 중심, 읽기 우선
지원 매체: Markdown, DOCX, PDF와 보고서에 포함되는 표·그림

## 우선순위

1. 공식 양식, 법적·접근성·개인정보·제출 요구
2. 프로젝트의 기존 템플릿과 디자인 정본
3. 검증된 내용, 데이터, 출처와 사용자 목소리
4. 이 기본 프리셋

## 정보 구조

모든 보고서에서 다음 역할을 찾을 수 있게 한다. 절 이름과 순서는 목적에 맞게 바꾼다.

| 역할 | 내용 |
| --- | --- |
| context | 독자, 목적, 기간, 범위와 전제 |
| takeaway | 핵심 결론 또는 확인할 질문 |
| method | 수행·분석·검증 방법 |
| evidence | 사실, 데이터, 실행 결과, 그림과 출처 |
| interpretation | 결과의 의미와 예상과 다른 점 |
| qualification | 제한, 불확실성, 미검증과 최신성 |
| action | 결정, 다음 조치, 담당자 또는 남은 질문 |

의사결정 보고서는 결론을 앞에 두고, 학습·실험 보고서는 질문과 수행 순서를 살린다.
모든 보고서를 동일한 장 제목으로 강제하지 않는다.

## 페이지 시스템

- 기본은 A4 세로이며 제출처가 지정하면 Letter·가로·양식을 따른다.
- A4 기본 여백은 좌우 20 mm, 위 20 mm, 아래 18 mm다.
- 표지는 제목, 한 줄 부제, 작성자·조직, 날짜·버전만 둔다. 짧은 보고서는 별도 표지를
  생략하고 첫 페이지 상단에 배치할 수 있다.
- 본문 상단의 큰 반복 헤더를 피하고, 필요한 경우 작은 문서명·버전만 사용한다.
- 하단에는 페이지 번호를 두고, 외부 제출이 아니라면 민감도·상태·기준일을 작게 표시할 수 있다.
- 소제목은 다음 본문이나 표와 같은 페이지에, 그림은 캡션과 같은 페이지에 유지한다.
- 한 페이지의 설명 역할이 둘 이상 충돌하면 글자를 줄이기보다 분리하거나 요약한다.

## 타이포그래피

한글을 포함하면 Noto Sans KR, 본고딕, 나눔고딕처럼 전체 문자 범위를 지원하는 글꼴을
사용한다. 조직의 허가된 글꼴이 있으면 그것을 우선한다.

| 역할 | 권장 범위 |
| --- | --- |
| 표지 제목 | 26–30 pt, Bold |
| 페이지·장 제목 | 18–22 pt, Bold |
| 절 제목 | 13–15 pt, Bold |
| 본문 | 10–11 pt, 행간 1.4–1.55 |
| 표·캡션 | 8.5–9.5 pt, 최종 출력에서 판독 가능한 크기 |
| 코드·경로 | 필요한 경우에만 고정폭 글꼴 |

제목 계층은 크기뿐 아니라 굵기, 전후 간격과 위치로 구분한다. 본문을 기술적으로 보이게
하려고 고정폭 글꼴을 사용하지 않는다.

## 기본 색상

조직 색상이 없을 때만 다음 의미 색을 사용한다.

| 역할 | 색상 |
| --- | --- |
| 본문 Ink | `#182230` |
| 보조 글자 | `#5E6B7A` |
| 주 강조 Deep Teal | `#1F5D7A` |
| 보조 강조 Amber | `#D98A3A` |
| 옅은 배경 | `#F3F6F8` |
| 구분선 | `#D6DEE5` |
| 위험 | `#B42318` |
| 확인·통과 | `#18794E` |

고채도 색은 제목 기준선, 작은 라벨과 핵심 값에만 사용한다. 상태는 색과 함께 단어·값·기호로
표시한다. 화면용 대비와 실제 PDF 인쇄 결과를 따로 확인한다.

## 구성요소

- 표: 첫 행을 구분하고 내부선은 가늘게 쓴다. 짧은 키 열은 좁히고 설명 열에 공간을 준다.
- 그림: 본문에서 먼저 언급하고, 아래 캡션에 무엇을 봐야 하는지와 필요한 출처를 적는다.
- 차트: 제목에 질문 또는 결론을 쓰고 단위·기간·기준선·출처를 표시한다.
- 코드: 판단에 필요한 구간만 쓰고 전체 파일은 링크나 부록으로 분리한다.
- 콜아웃: 결론, 결정, 위험, 제한처럼 독자가 놓치면 안 되는 한 가지 메시지에만 쓴다.
- 목록: 순서가 있으면 번호, 동등한 집합이면 글머리표를 사용한다. 긴 문단을 장식적으로
  쪼개지 않는다.

## 밀도 변형

- `calm`: 표지, 경영 요약, 짧은 의사결정 문서
- `standard`: 일반 기술·프로젝트·분석 보고서의 기본값
- `compact`: 운영 점검표와 반복 비교 표. 본문 크기를 희생하지 않고 표·부록으로 분리한다.

한 문서 안에서 밀도를 임의로 바꾸지 않는다. 중요한 장만 여백과 크기를 키울 수 있다.

## 피할 요소

- 근거 없는 그라데이션, 유리 효과, 아이콘 카드와 큰 색상 면
- 표를 페이지 레이아웃 도구로 사용하는 방식
- 작은 회색 글자, 과도한 라운드 박스, 장마다 달라지는 장식
- 표지 디자인을 본문 모든 페이지에 반복하는 방식
- 로고·폰트·서드파티 구성의 권리 확인 없는 복제
- PDF가 잘 보인다는 이유로 편집 가능한 정본까지 검증됐다고 말하는 방식

## 형식별 적용

- Markdown: 의미 구조와 근거의 정본으로 사용한다. 렌더러 전용 장식 문법을 최소화한다.
- DOCX: 네이티브 제목·목록·표·캡션 스타일을 사용하고 직접 서식을 예외로 둔다.
- PDF: 최종 내보내기를 다시 열어 전 페이지, 링크, 폰트, 텍스트 추출과 페이지 번호를 확인한다.
- 차트·도식: 원본 데이터 또는 편집 가능한 소스를 보존하고 최종 삽입 크기로 판독성을 확인한다.
