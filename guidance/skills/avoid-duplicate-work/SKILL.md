# 중복 작업과 재발 방지

한 프로젝트의 미완료 작업을 이어받거나 여러 에이전트의 결과를 통합할 때 사용한다. 일반적인 단일 수정에는 끼워 넣지 않는다.

1. **현재 정본 한 곳에서 시작한다.** 프로젝트가 지정한 `context/PROJECT.md` 같은 정본의 목적·현재·HOLD·다음 행동만 읽는다. 그 뒤 현재 Git 상태·원격 HEAD·운영 revision을 필요한 범위에서 다시 읽는다. 통상 재개에서는 오래된 대화와 보고서를 처음부터 전수 재독하지 않는다. 사용자가 전체 종합을 요청하면 지정 범위의 과거 승인·미완료를 필요한 만큼 대조한다.
2. **결과별로 대조한다.** 같은 기능 이름이어도 `소스 구현`, `원격 반영`, `운영 배포`, `실사용 검증`은 별도 상태다. 각 결과에 현재 증거와 남은 조건을 붙인다. 이미 운영에서 검증된 결과는 새 변경 근거가 없으면 다시 만들거나 배포하지 않는다.
3. **한 저장소에 한 작성자를 둔다.** dirty 파일과 다른 작업자의 worktree를 보존한다. 겹치는 브랜치는 통째로 병합하지 말고 현재 정본과 파일·동작 단위로 차이를 확인한다. 새 작업 단위는 소유 파일, 완료 기준, 통합 위치가 분명할 때만 나눈다.
4. **같은 실패를 반복하지 않는다.** 검색은 좁은 파일·키워드로 시작하고 관련 읽기는 묶는다. 검사 실패 뒤에는 입력·환경·코드 중 바뀐 것이 무엇인지 확인한 후 재실행한다. 결과가 같은 장시간 빌드, 브라우저 확인, 상태 조회를 근거 없이 반복하지 않는다.
5. **재발 원인을 작게 막는다.** 실제 회귀가 확인되면 가능한 한 코드·검증·출시 절차에 직접 가드를 넣는다. 예: 배포 대상 불일치, CI 성공 속 필수 단계 건너뜀, 오래된 복구 version, 누락된 인덱스. 실패 증상, 원인, 가드, 검증, 복구 지점은 기존 정본 또는 관련 runbook에 한 번만 기록한다. 로그와 대화 원문은 복제하지 않는다.
6. **끝난 범위를 증명한다.** 검사와 실제 UI·운영 readback은 현재 모델 정책과 사용자가 명시한 범위에서만 수행한다. 코드 통과와 고객 성공은 별개다. 이미 승인된 commit·push·배포는 진행하되 적용 응답과 실제 작동을 구분한다. 불가능한 항목은 관찰된 차단 원인, 재개 조건, 다음 담당만 남긴다.

토큰 수 자체를 성과로 삼지 않는다. 중복 조사·중복 작성·무의미한 재시도를 줄이되, 새 위험을 해결하는 데 필요한 검증은 생략하지 않는다.

## 한 단계의 보류와 가능한 작업 구분

원격 갱신 경로가 없다는 이유로 로컬 정본의 유효한 개선까지 함께 보류하지 않는다. 원본 확보·기능 병합·홈 배포·원격 적용·실사용을 항목별로 기록한다. 저장 전 preimage 거절이 명확하면 무변경으로 남기고 fresh 전체 본문과 차이를 검토해 새 변경 계획을 세울 수 있다. 저장 응답 불명은 이 경우와 구분하며 재전송하지 않는다.

기록과 인계의 중복은 control-project-work의 [기록 수명과 통합](../control-project-work/references/control-contract.md#기록-수명과-통합)을 따른다. 새 작업 번호로 같은 미결을 다시 만들거나 서로 다른 중앙의 완료 표지를 합쳐 전체 완료로 올리지 않는다.
