# 한도 안내와 실제 연결 거절

## 사용자 운영 기준

이 운영 환경에서 화면의 ‘워크스페이스 구성원이 사용 한도에 도달했습니다’ 안내는 Codex 사용량 관련 안내다. 이 배너는 일반 Chat 지피티 작업의 중단·대기·한도 회복 조건으로 쓰지 않는다. 사용자는 기존 OCX가 계정 전환과 소진 전 차단을 담당한다고 명시했다. 코덱스와 지피티는 안내를 무시하고 승인된 일을 이어간다. OCX 설정 변경·수동 계정 교체·자동 충전·Work 전환은 이 기준에 포함되지 않는다.

실제 요청이 quota/rate-limit으로 거절되거나 OCX가 차단하면 해당 요청·경로의 응답에 따라 처리한다. 안내 배너를 실제 거절로 바꾸거나, 실제 거절을 배너라며 무시하지 않는다. 일반 Chat과 요청된 xhigh를 유지한다.

## 429를 좁히는 순서

429라는 숫자만으로 Codex·ChatGPT·OCX 한도를 단정하지 않는다. 실패한 실제 도구, 단계, 응답 발행 주체를 먼저 기록한다. MCP SSE probe의 429는 연결 중계 응답이며 모델 추론의 quota 거절과 별개다.

ChatGPT 대화 목록의 `listing_http_429`는 ChatGPT 조회 요청의 실제 제한 응답이다. 이 경우 터널·Task 재시작으로 처리하지 않는다. 지정된 conversation ID는 해당 대화만 조회하고 전체 계정·프로젝트 목록을 훑지 않는다. 제목·날짜 검색은 요청 수를 제한하고 전수 조회 여부를 명시한다. 응답의 안전한 경로·HTTP 상태·Retry-After 초만 남기며 인증 헤더·쿠키·오류 원문은 저장하지 않는다. Retry-After를 받지 못했으면 미상으로 기록한다. 자동 반복·다른 계정 전환으로 우회하지 않고, 확정된 읽기 실패와 변경 결과 불명을 구분해 원 요청을 조정한 뒤 필요한 새 조회만 수행한다.

기존 exact 터널 ID·Task·로컬 MCP 준비·최근 서버 기록과 비교한다. 꺼진 연결은 프로세스 부재를 확인하고 시작 잠금의 owner PID를 확인한다. 죽은 owner의 잠금만 원문·해시·원본 Task 설정을 보존하고 분리한 뒤 기존 Task를 시작한다. 현재 owner나 PID 재사용·신원 불명이면 건드리지 않는다. credential·프로필·연결 ID와 권한을 바꾸지 않는다.

복구 뒤 같은 실제 도구의 성공 응답을 회수해야 해결로 기록한다. 로컬 프로세스 기동만으로 원격 호출 성공이라 하지 않는다. 불명 변경 요청은 재발신하지 않고 기존 요청을 조정한다. 인증·보안 거절은 우회하지 않는다.

## 한도 안내와 연결 오류

화면의 workspace 사용 한도 안내는 이 환경의 일반 Chat 작업을 중단하는 조건이 아니다. 기존 OCX가 계정 전환과 소진 전 차단을 담당한다. 실제 요청 거절·MCP 연결 429와 구분하는 [운영 기준](quota-and-connection.md)을 따른다. 일반 Chat·xhigh를 유지한다.

Notion 쓰기는 [목적지 원칙](../../aicc-workspace-operator/references/notion-file-transfer.md#notion-목적지-원칙--공통-정본)을 먼저 따른다. 확인된 기존 목적지/부모 exact ID 없이는 HOLD하며 draft/root/parent 생략으로 최상위를 자동 생성하지 않는다.
