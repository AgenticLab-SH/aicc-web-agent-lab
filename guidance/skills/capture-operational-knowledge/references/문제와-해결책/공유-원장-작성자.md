# 공유 원장 작성자 한 명

- 판정: 채택, 현재 운영 조정. 저장 엔진의 근본 해결 판정은 아니다.
- 증상/범위: 공유 aggregate JSON의 동시 read-modify-write 뒤 실제 성공 필드가 빠짐.
- 원인: 서로 다른 helper가 같은 집계를 갱신하며 변경이 소실된 운영 사례. 필드 부재가 원격 미접수를 뜻하지 않는다.
- 대안 비교: 외부 요청 반복은 중복과 비용을 만든다. 작성자 한 명이 갱신을 직렬화하고 원래 도구 영수증으로 누락 메타데이터만 조정하는 방식을 채택한다. 원자적 교체만으로 stale read 갱신 소실까지 해결되지는 않는다. lock/CAS/version 충돌 처리는 유력한 기술 대안이지만 해당 원장에 구현·검증한 근거가 없으므로 후보로 남긴다.
- 최소 절차: [공유 영수증 동시 갱신](../../../web-gpt-driving/references/failure-solutions.md#공유-영수증의-동시-갱신-충돌)을 따른다. 작업자는 짧은 근거를 담당 writer에게 넘기고 writer만 기존 항목을 갱신한다. 전체 원문·로그를 집계에 복사하지 않는다.
- 중단/갱신: 실제 성공 출력이 없으면 성공을 복원하지 않고 UNKNOWN. 다중 writer가 필요해지면 소유 계약과 충돌 해결을 먼저 설계한다. 단일 writer만으로 크래시 내구성·원자성·모든 경쟁을 해결했다고 하지 않는다.
- 근거: 2026-10-16 KST 원래 성공 도구 출력과 집계 누락의 대조, provenance가 붙은 메타데이터 복구 기록. 저장 엔진의 동시성 시험이나 새 CAS 구현은 없다. 재전송 방지와 반복 대조 감소가 선택 이유이며 토큰/시간 실측은 없다.

## 긴 문맥과 중복 인계로 현재가 흐려지는 경우

- 판정: 운영 절차 채택, 자동 충돌 방지·토큰 절감 실측은 미입증.
- 관측: 2026-10-18 KST 종합 시 중앙 현재/인계 약 20KB씩, AICC 현재 문서 약 277KB, 자동매매 현재 문서 약 429KB에 과거 단계가 함께 남아 있었다. 이전 중앙이 조사만 배정한 뒤 종료해 실행 후속이 빠졌고 새 중앙에 재인계한 실제 사례도 있었다.
- 구분: 긴 파일만으로 모델 실패의 단독 원인을 확정하지 않는다. 현재 상태와 과거 관측의 혼합, 여러 중앙의 작성권·범위 전달은 관측된 운영 요인이다.
- 선택: 기존 정본의 현재 항목 교체, 이력 링크, 안정 작업 ID, 단일 writer와 인수/반납으로 보완한다. 날짜별 보고를 더 만들거나 모든 기록을 삭제하는 접근은 미결 근거를 잃게 한다.
- 최소 절차: [기록 수명과 통합](../../../control-project-work/references/control-contract.md#기록-수명과-통합). 실제 적용·미해결은 소유 프로젝트에만 둔다.
- 한계: 파일 잠금/CAS/중복 실행 엔진과 자동 압축은 이 문서 변경으로 구현되지 않는다. 복구본·불명 attempt는 완료 조건이 풀리기 전 보존한다.
