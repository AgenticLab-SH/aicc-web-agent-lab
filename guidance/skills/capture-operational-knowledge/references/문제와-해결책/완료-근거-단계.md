## 공유 실행기 추가 뒤 중지·복구 대상 누락 · 2026-11-20

- 채택: 기존 전환기의 공통 소유 판별에 같은 release의 정확한 실행 파일 경로와 단일 `--run` 인수를 함께 확인한다. `--check`, 다른 이미지, 경로 문자열만 포함한 명령, 관측 불가 프로세스는 보존한다. 기존 PID·생성 시각·명령 SHA 재대조와 active/UNKNOWN 검사는 유지한다.

## 큐의 일시정지와 전송 불명 집계 · 2026-11-16

- 증상: 원 역할에 `submissionUncertain=true`가 있어도 요약이 `paused`를 먼저 세면 불명0·확인0으로 보인다. 실행 정지와 전송 결과 불명은 다른 사실이다.
- 채택: 기존 native 원장은 보존하고 공통 읽기 projection에서 불명을 우선 집계한다. 범주는 중복 계수하지 않고 불명 실행의 ready/running 역할을 광고하지 않는다. 웹은 최대 표시 목록의 불명과 전체 집계를 구분하며 조회 실패 시 마지막 성공 목록과 실패 안내를 보존한다.
- 근거: paused/terminal/running 반례와 비밀 비노출 회귀, 실제 native 요약 unknown1 및 격리 Chrome 빈/불명/실패보존·확대글자 확인. 이 결과는 원 전송 성공·자동재개·운영 웹 배포 증거가 아니다.
- 설치판 검증은 현재 owner의 정확한 두 target과 무관한 역사 target을 분리한다. 전체 역사 탭 보호 조건 실패를 현재 설치 guard 부재로 단정하거나 UNKNOWN 탭을 임의 수정하지 않는다. 프로필 신원·원 요청·등록된 관리자 경로는 유지한다.

- 근거와 한계: 실제 Windows PowerShell 모의helper를 포함한 인증API 12검사·후보4검사 및 격리 Chrome 3폭/미결버튼차단 PASS. 운영 웹 설치·자연 quota 리셋 자동복귀는 별도다. 사용자 명시 재개는 exact mux 공식 `/goal resume` 후 같은goal active와 실제 도구착수로 확인한다.

## 기한이 지난 실행의 읽기 전용 상태 조회

- 증상/원인: 상태 조회기에 특정 관제 run의 종료 날짜를 상수로 넣어 종료 후 원 대화·보존된 미결까지 읽지 못했다. 당시 검사도 같은 날짜를 써 시간이 지나면 실패했다.
- 수리: 읽기 전용 조회는 기한 없음·미래·과거를 받아 현재 만료 여부만 반환한다. 잘못된 날짜와 다른 대화는 계속 거절한다. 실제 발신·재개·소유권 권위는 조회 결과로 부여하지 않는다. 실행기의 원래 기한 제한은 그대로 유지한다.
- 근거: 2026-11-10 영향 범위 16검사 PASS와 실제 원 CLI의 기한 없는 조회 성공. 모델 발신·worker 시작·goal 재개는 모두 0이며 설치나 자동 한도 복귀의 증거가 아니다. 날짜 관련 검사는 현재 시각 기준 미래값과 고정 과거값을 구분한다.

- 판정: 채택. 근거를 분리하는 운영 원칙이며 미완료 구현을 해결 사례로 승격하지 않는다.
- 증상/범위: queue·quota·설치·화면 표시·스킬 이름을 실제 발신·진척·완료와 혼동함.
- 원인: 서로 다른 단계의 증거를 대신 사용한 판단 오류. OCX 풀 quota는 해당 대화의 실제 모델 경로를 증명하지 않는다.
- 대안 비교: 단일 ‘정상/완료’ 표시는 빠르지만 장애 경계를 감춘다. 현재 결정에 필요한 단계와 미확인만 짧게 남기면 중복 조사와 허위 재개를 줄인다. 매번 전체 health/inventory를 재검사하는 방식은 필요하지 않다.
- 최소 절차: [전달 수단 부재](../../../web-gpt-driving/references/failure-solutions.md#전달-수단-부재와-정상-생성은-한도-차단이-아니다)를 참조한다. source→홈/원격 저장→설치→실제 호출, queue→Claim→공식 ACK→marker 새 turn→목표 완료를 별도 기록한다. UI상 Stop=1·빈 입력·경고0이면 ‘UI상 생성 중·실제 진척 미확인’이다. 새 응답·도구 결과·산출물 변화가 있어야 그 범위의 진척을 말한다.
- 중단/갱신: 시간이나 같은 SHA만으로 진행/정체/한도 차단을 확정하지 않는다. 시간만으로 중지할 새 규칙도 만들지 않는다. 실제 경로/기능이 추가되면 그 근거만 갱신한다. 내장 goal blocked를 임의 해제하지 않는다.
- 근거: 2026-10-16 KST helper 설치 영수증·모바일 후보 조립·Web 스킬 저장과 두 대화 UI 관측. 무인 공식 발신 계약, 모바일 공개 전환, 실제 폰 제어, 이후 코드 변경의 검증은 현재 프로젝트의 미해결이다. 새 스킬 native 호출도 미실행이다.
## CDP 신원 선택 미지원과 실제 인증·과거 반환 HOLD의 구분 · 2026-11-09

- **관측 증상:** 등록된 Host의 브라우저 호출이 `EXACT_REGISTERED_CDP_IDENTITY_REQUIRED` / `NOT_DISPATCHED`를 반환했다. 기존 `aicc_host_capabilities`는 `cdpIdentityRequired=true`만 알려 주고 정확한 `browser_identity` 선택 목록은 주지 않았다.
- **확인 원인과 미확정:** Host 소스에 ID 발견 출력 계약이 없는 점은 확인됐다. 이 거절은 드라이버 호출 전 사전 검증 실패이며 로그인 실패·계정 보안 거절 증거가 아니다. 실제 브라우저 로그인, 리소스 회수와 역사적 UNKNOWN 원인은 별도로 **미검증**이다.
- **실패·위험한 대안:** 포트·계정명 추측, 첫 ID 자동 선택, 원 요청 재송, 다른 owner/Aside로 우회, journal·HOLD 삭제는 사용하지 않는다. 공개 ID 목록은 로그인·가용성 증거가 아니다.
- **최소 수리:** 기존 owner-pinned 등록 CDP 목록에서 정확한 `identityId`만 `aicc_host_capabilities.cdpIdentityDiscovery.identityIds`로 돌려주고, 서로 다른 owner·잘못된 등록은 목록 전체를 거절한다. caller에게 owner·account·hash·endpoint·profile·비밀을 반환하지 않는다. 선택 이후의 대상/로그인 증명과 기존 HISTORY_UNPROVEN은 계속 독립적으로 검사한다.
- **검증·배포 단계:** 합성에서 `capabilities → 명시적 ID 선택 → 작업 → 정상 반환`, 등록 없음, 다른 owner, 잘못된 등록, Aside, 역사적 HOLD를 분리했다. 소스 담당은 신규10검사·설치0으로 반환했고, 중앙은 영향 범위 CDP/역사복구50검사 PASS→실제8도구 후보 격리실행→정식 Prepare·실독립READY·empty consumed drain·Apply→설치hash·실원격 capabilities 신원목록·Workspace조회 성공을 인수했다. 실제 Host open·FBTT 인증화면 QA 재시도는0이며 역사적 HOLD는 유지했다. 도구 목록 성공을 로그인·브라우저 E2E로 승격하지 않는다. ## 검색 미지원과 보안 거절의 구분

2026-10-17 KST 확인: 중간 bridge는 공식 alpha/search를 전달했지만 다음 어댑터의 POST 허용 목록에서 빠져 공통 owner 오류 문구와 404를 반환했다. 해당 지원 누락과 실제 upstream 인증·보안 거절은 다른 원인이다. 공식 공급자 검색 처리기를 기존 계정·모델·quota admission에 연결해 격리 검사와 불변 릴리스 적용을 마쳤다. 독립 복구의 fresh READY·실제 idle 뒤 설치 ACTIVATED/exit0, 단회 worker 정상 종료와 capsule CLOSED를 확보했다. 설치 뒤 원래 기본 web.run 검색1회가 Microsoft Support 실제 결과·본문·공식URL을 반환했다는 중앙 실행 영수증과 공식 thread의 검색 활동을 회수했다. 이는 이 검색 경로의 실제 성공이며 일반 회귀·다른 기능 완료는 아니다. 다른 기존 검색 커넥터의 성공도 원래 경로의 복구 증거로 대신 쓰지 않는다.

채택할 판단은 확정 실패→원인별 복구→허용된 원래 동작 재시도다. 불명 전송이나 명시적 보안 거절에는 이 재시도 규칙을 적용하지 않는다. 정상 적용을 막는 실제 활성 작업과 독립 복구 조건은 보존하고 정확한 기존 적용 절차를 남긴다. 현재 설치·남은 조건은 프로젝트 정본을 따른다.

- 선택: 계정·프로필·브라우저를 바꾸거나 탐지 옵션을 숨겨 인증을 재시도하지 않는다. 기존 창/프로필을 보존하고 공식 지원 범위를 검토한다. 일반 네트워크/뷰어 실패의 단회 재시도 규칙은 명시적 provider 보안 거절에 적용하지 않는다.

- 갱신 조건: 공식 지원 답변이나 실제 허용 경로 근거가 생길 때 현재 판단만 갱신한다. 사용자 직접 전달이 성공해도 자동화 로그인 복구로 승격하지 않는다.
