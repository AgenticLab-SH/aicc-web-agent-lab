# 문제와 해결책 남기기

현재 상태·미해결·HOLD·다음 담당은 기존 context/PROJECT.md에 변화만 남긴다. 이 스킬에는 다음 조사나 중복 동작을 줄일 수 있는 판단 기준만 둔다.

1. [사례 색인](references/문제와-해결책/색인.md)에서 증상·환경을 검색하고 관련 사례 1~2개만 읽는다. 상세 절차의 기존 소유 스킬이 있으면 연결하며 본문을 복제하지 않는다.
2. 반복됐거나 조사 비용이 컸거나 다음 결정을 바꿀 실패는 작업을 끝내기 전에 기존 사례에 기록한다. 같은 실패를 다시 시도하기 전 기존 원인·실패한 대안·변경된 입력/환경을 확인한다. 원인이 확인되면 문안뿐 아니라 담당 구현·회귀검사·설치/운영 경계의 가장 작은 재발 방지를 수행하고, 못한 단계와 해제 조건을 명시한다. 단순 오류·전체 로그·대화 원문·비밀·가짜 절감 수치는 제외한다.
3. 같은 원인과 환경은 기존 항목을 갱신한다. 원인이 불명이면 증상과 환경을 임시 키로 삼고, 같아 보인다는 이유로 확정 원인으로 합치지 않는다. 원장 작성자 한 명이 갱신하며 다른 작업자는 변경 근거만 넘긴다.
4. 사례에는 증상/범위, 확인 원인과 불명, 실패/대안, 선택 이유, 최소 절차의 위치, 중단/갱신 조건, 근거 종류·관측일·한계를 적는다. 판정은 채택·조건부·후보·폐기 중 하나다. 반례가 생기면 기존 판정을 좁힌다.
5. 현재 근거에서 신뢰성·작업량·재발 가능성·토큰/시간 절약을 비교한다. 성공 한 번을 근본 해결이나 최선 보장으로 쓰지 않는다. 소스·배포·실제 실행·사용자 사용 완료를 분리한다. 확인은 현재 권한과 모델 정책 안에서만 한다.

사례를 추가할 때 짧은 검색어와 링크만 색인에 넣는다. 다른 스킬에는 호출점만 둔다. 현재 계정·포트·프로세스·경로는 공유 사례에 고정하지 않고 소유자의 정본과 기존 등록 정보를 따른다. 옛 Windows 운영 기록의 적용 범위는 [역사 기록 안내](references/webgpt-aicc-windows.md)를 읽는다.
