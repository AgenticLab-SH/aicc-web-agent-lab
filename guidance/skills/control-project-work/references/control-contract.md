# 상태와 위임 계약

## 기존 정본에 남길 것

사람용 상태는 기존 `context/PROJECT.md`, 기계용 추적은 현재 쓰는 state에 변화만 반영한다. 다음 표는 필드의 의미이며 새 파일이나 새 스키마 생성 명령이 아니다. 중앙 소유 정본은 작업자가 덮어쓰지 않고 변경 근거만 반환한다.

| 항목 | 필요한 내용 |
|---|---|
| 목표와 경계 | 기존 목표·최신 사용자 수정·제외 업무·완료 조건 |
| 작업 ID/root/owner | 동일 작업을 이어가는 ID, 정확한 Git root와 쓰기 경로, 담당자 |
| 대상과 cursor | 정확한 Codex thread·host 또는 Web URL/등록 신원, 마지막 공식 wait cursor |
| 의존성 | 앞선 작업 ID와 필요한 결과. 다른 root의 구현을 한 작업에 섞지 않는다 |
| 근거 단계 | source/배포/접수/실제 호출/업무 완료 중 확보한 단계와 근거 위치·관측 시각 |
| 다음 행동 | 주체와 실행할 한 동작. 불명 원요청을 새 intent로 만들지 않는다 |
| HOLD/재개 | 관측 사실, 해제 조건, 다음 owner, 기한 또는 외부 사건 |

기존 승인 목표가 남았으면 내장 goal blocked와 사용자 목표를 함께 보존한다. 로컬 원장 상태를 근거 없이 active로 바꾸지 않는다. branch/dirty·복구 위치는 해당 작업에 필요할 때 기존 항목에 결속하며 매회 전체 감사하지 않는다. 시간은 사용자에게 KST로 표시하고 API 원관측 UTC는 필요한 기계 필드에 유지한다.

비밀·원문 대화·툴 출력·로그·반복 스냅샷을 복제하지 않는다. 완료 결과는 다음 결정을 바꾸는 사실과 근거 링크만 흡수한다. 현재 확인하지 않은 과거 결과는 관측 시각과 한계를 밝힌다.

## 짧은 위임문

다음 틀에서 결정을 바꾸는 내용만 쓴다.

> 목적: <완료할 한 결과>. 소유: <root/경로와 exact 기존 대상>.
> 보존/제외: <dirty·계정·원본, 이번에 하지 않을 일>. 다른 작성자가 있으니 그 변경을 되돌리지 않는다.
> 완료 조건: <필요한 산출물과 근거 단계>. 검증은 현재 모델 정책과 명시 요청 범위만.
> 실패 시: <실패 stage·원전송 접수 상태·재개 조건·다음 owner>만 반환하고 불명 전송은 재시도하지 않는다.

사용자가 새 대화를 요청했을 때만 공식 create_thread를 쓴다. 승인된 하위 위임은 현재 제공된 collaboration 도구를 사용한다. 다른 대화의 위임문만으로 사용자 메시지 발신 권한을 새로 만들지 않는다. 사용자 승인이 이미 있는 대상은 같은 승인을 다시 묻지 않는다.

## 정리 요청이 있을 때만

이관·삭제 전 정확한 호출자와 경로를 읽고 복구 수단을 정한다. clean tracked 원본은 Git revision, 수정/미추적 원본은 바이트 보존 백업을 제거 대상 밖에 둔다. 해시는 동일성 근거이며 복구 수단 자체가 아니다. Windows 이동/삭제는 확인한 절대 하위 경로와 PowerShell LiteralPath를 쓴다. 광역 정리나 사용자 원본 삭제를 스킬 적용의 부수 작업으로 만들지 않는다.

기존 `scripts/prepare_cleanup_manifest.py`는 삭제하지 않는 정확 대상 inventory 도우미다. 정리 요청과 실행 정책이 허용할 때만 사용한다. 복구 manifest가 필요하면 기존 정리 기록을 재사용한다.

```json
{
  "created_at": "ISO-8601",
  "scope_root": "absolute path",
  "reason": "approved cleanup scope",
  "targets": [{
    "path": "exact absolute path", "type": "file or directory",
    "size": 0, "sha256": null, "git_root": null,
    "git_revision": null, "git_state": "tracked-clean, tracked-modified, or untracked",
    "callers": [], "recovery_source": "Git revision, backup, or trash"
  }],
  "verification": []
}
```

위 verification은 허용된 확인 기록만 담는다. 모델 정책상 금지된 사후 시험을 요구하지 않는다. 복구 자료는 복구 필요가 끝나기 전까지 보존하며 영구적인 회차별 보고 원장으로 키우지 않는다.

## 기록 수명과 통합

- 새 파일을 쓰기 전에 기존 소유 문서·절, 소비자와 보관 위치를 정한다. 한 업무의 현재 상태는 프로젝트 정본 한 곳, 중앙은 작업 ID·담당·근거 링크만 소유한다. 시각별 새 보고서·마감 원장·handoff 사본을 계속 만들지 않는다.
- 현재 절은 다음 결정을 바꾸는 사실로 교체한다. 단계별 일지는 기존 journal이 맡는다. 긴 이력을 분리할 때 unique 승인·결정·미결·복구 위치를 먼저 현재 절에 남기고 기존 역사 위치에 한 번만 보존한다. 크기는 분리 신호이지 일률적인 삭제 기준이 아니다.
- 전체 종합을 요청받으면 지정 대화의 최신 공식 결과와 필요한 과거 요청·기존 산출물을 대조한다. 숨은 미완료·해제·불명 전송·사람 개입도 포함하고 출처 시점을 붙인다. 원문 전체를 새 문서로 복제하지 않는다.
- 인계는 기존 작업 ID·완료 조건·미결 attempt를 유지한다. 이전 중앙의 쓰기·발신 중단과 새 중앙의 인수를 결속하고 현재 writer 표를 갱신한다. 보관할 대화는 참고 출처와 실행 owner를 구분하며 옛 thread를 자동 재개 대상으로 남기지 않는다.
- 결과는 요청 적합성·근거 단계·시점을 판단해 필요한 결정만 흡수한다. 다른 대화의 제안이나 완료 표지를 전체 목표 완료로 바꾸지 않는다. 목표가 변경됐다면 기존 목표와 변경 범위를 명시한다.
- 정리 목록은 현재 정본·역사·복구본·불명 영수증·재생성 가능한 캐시로 나누고 exact 경로·사용처·복구 근거를 남긴다. 사용자 검토 대기 기록과 활성 consumer 파일은 유지한다. 확인된 빈 임시 출력은 좁은 경로로 정리할 수 있다.
- 배포 홈은 기존 배포기, 지피티는 기존 변경 동기화 manager를 쓴다. 로컬 변경의 Web 영향과 미지원/백업 조건을 기록하며 로컬 배포를 원격 저장·설치·실제 사용으로 보고하지 않는다.
