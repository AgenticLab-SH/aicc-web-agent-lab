# 한영 UI 품질

기존 디자인 시스템·기능·사용자가 정한 언어와 말투를 먼저 따른다. 새 화면이나 확인된 품질 문제에 필요한 부분만 적용한다. 작은 수정에 전체 재설계·새 문서 묶음·새 라이브러리를 요구하지 않는다.

## 공통 기준

- 정보의 우선순위와 주요 행동을 분명히 하고 같은 역할의 요소에 같은 글꼴·색·간격·명칭을 쓴다. 장식·그림자·애니메이션은 제품 목적에 필요할 때 사용한다.
- 별도 기준이 없는 한영 콘텐츠 UI는 Pretendard Variable을 우선 후보로, SUIT Variable을 대안으로 삼는다. Windows 시스템형 UI와 모바일은 플랫폼 기본 글꼴·접근성 확대를 존중한다. 정상인 플랫폼 기본 창 구성이나 기존 브랜드를 일괄 변경하지 않는다.
- 코드·로그에는 JetBrains Mono 등 고정폭 글꼴과 한글 폴백을 사용한다. 설치·번들링 전 실제 버전의 라이선스·재배포·고지 조건을 확인한다. OS 전체 폰트 설치를 기본값으로 삼지 않는다.
- 기준이 없는 웹 본문은 16px 상당·줄간격 1.6, 작은 라벨 14px, 제목 줄간격 1.3~1.4를 출발점으로 쓴다. 본문 400, 버튼 500~600, 제목 600~700·본문 자간 0을 후보로 삼되 실제 글꼴 지원·기존 토큰·플랫폼 단위를 따른다. 수치를 Windows DIP나 모바일 sp/pt에 그대로 강제하지 않는다.
- 내용에 맞게 영역이 늘어나거나 재배치되게 한다. 필수 안내·오류·버튼 이름을 고정 높이·강제 한 줄·글자 축소로 숨기지 않는다. 한글 어절은 자연스럽게 유지하고 긴 영문·숫자·URL·경로는 안전하게 표시한다.
- 말줄임은 의도한 미리보기에만 쓴다. 전체 값 보기·확장·복사 등 키보드·포인터·터치로 접근 가능한 경로를 둔다. 로그·편집기·넓은 표는 목적에 맞는 스크롤을 사용하고 전역 줄바꿈으로 구조를 망가뜨리지 않는다.
- 기본·비활성·선택·포커스·로딩 상태에서도 글자와 조작 대상을 읽을 수 있게 한다. 색만으로 상태를 알리지 않는다. 일반 텍스트 대비 4.5:1, 큰 글자 3:1을 목표로 하며 미측정을 준수 완료로 쓰지 않는다.
- 기능의 목적·사용법·결과·불가 이유를 필요한 위치에 짧게 제공한다. 핵심 안내는 항상 보이게 하고 호버·키보드 포커스·터치 도움말로 보완한다.

## UI 문구

기존 언어 정책이 없으면 한국어를 기본으로 한다. 영어 지원은 요청·제품 범위에 맞추며 모든 화면에 이중 언어나 새 번역 시스템을 강제하지 않는다.

일반 사용자 안내는 명료하고 친근한 존댓말로 쓴다. 기존 제품·사용자 문체를 우선하고, 기준이 없을 때만 해요체를 후보로 삼는다. 사용자가 저자로 나가는 제품 문구는 `write-as-demo-owner`의 현재 제품 문구 정본을 먼저 따른다. 그 정본의 기본 `합니다`체를 UI 예시만 보고 해요체로 바꾸지 않는다. 법적 고지·기업용 보고의 격식도 보존한다. 결과를 먼저 말하고 다음 행동을 구체적으로 안내한다. 버튼은 실제 행동 이름을, 오류는 확인된 문제와 가능한 해결 방법을 쓴다. 사용자 입력·서버 메시지·고유명·계약 문구를 임의로 고치지 않는다. 영어는 직역 대신 같은 행동과 의미를 자연스럽게 전달한다.

| 상황 | 예시 |
|---|---|
| 저장 완료 | 저장했어요. |
| 입력 오류 | 날짜를 확인해 주세요. 시작일은 종료일보다 빨라야 해요. |
| 통신 오류 | 서버에 연결하지 못했어요. 연결을 확인한 뒤 다시 시도해 주세요. |
| 실행 버튼 | 변경 사항 저장 / Save changes |

실제 저장·전송 결과가 불명확하면 성공이나 안전한 재시도를 약속하지 않는다. 확인된 상태와 다음 행동을 쓴다.

## 화면 근거와 완료 보고

검증을 수행할 수 있는 경우 변경 범위에서 긴 한영 문구·숫자·URL·특수문자, 빈 값·로딩·오류, 좁은 화면·글자 확대·폰트 대체/로딩 실패와 상태별 조작을 관찰한다. 웹의 200% 글자 확대와 320 CSS px 재배치는 별도 조건이며 본질적으로 2차원 배치가 필요한 넓은 표·지도 등의 예외를 구분한다. screenshot 하나나 build 성공만으로 전체 사용성을 보장하지 않는다.

변경 영향에 맞는 검사 시나리오를 선택하고 공통 지침과 사용자 요청 범위에 따라 완료 검증을 수행한다. 모델 이름만으로 생략하지 않는다. 구현·홈 반영·AICC 읽기·지피티 스킬 등록/설치/사용·실제 화면 관찰을 구분하고 실행하지 않은 검증은 `검증 미실행`으로 보고한다.
