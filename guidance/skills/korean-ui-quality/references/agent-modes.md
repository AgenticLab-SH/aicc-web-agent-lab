# 코덱스와 지피티의 적용 방식

지피티는 ChatGPT Web 일반 Chat, 코덱스는 로컬 Codex CLI·Desktop이다. 아래에서는 AICC로 로컬 스킬을 읽어 활용하는 방식과 ChatGPT에 스킬을 별도로 등록·설치하는 방식을 구체적으로 구분한다. 이 구분이 모든 UI 작업에 별도 스킬 설치를 요구하는 것은 아니다.

## 코덱스: 저장소와 구현

1. 가까운 지침·현재 작업·관련 컴포넌트·폰트/번역 리소스·토큰과 영향을 받는 화면만 파악한다. 기존 수정과 서비스·계정·로그인을 보존한다.
2. 원문 손상·UTF-8 송수신 손상·올바른 문자열의 layout 잘림을 구분해 수정 위치를 정한다. 한글 깨짐을 폰트 변경으로 일괄 해결하지 않는다.
3. 사용자 여정과 기존 stack을 유지하며 관련 token/component/resource에 작은 변경을 적용한다. 컨테이너 크기·줄바꿈·스크롤·전체 값 접근을 함께 설계한다.
4. 검사 방법은 준비하되 실제 검증은 현재 모델 정책과 사용자 요청에 따른다. 작성·적용·배포·화면 관찰의 근거를 각각 보고한다.

## 지피티: 설계·문구·연결된 작업

- 제공된 요구·자료·화면의 근거로 정보 순서·상태별 문구·긴 텍스트 처리·플랫폼별 구현 조건을 정리한다. 작은 문구 수정에 별도 분석표나 코덱스 인계를 강제하지 않는다.
- 이미지 생성 시안의 한글은 편집 가능한 UI 텍스트·접근성·실제 글꼴 렌더의 증거가 아니다. 문구를 편집 가능한 원문으로 함께 제공한다. 정지 화면으로 hover·focus·scroll·저장 성공을 판단하지 않는다.
- PC의 코드·지침이 필요하면 기존 AICC Workspace에서 등록된 `local-skills` 등 실제 별칭을 찾는다. 같은 lease의 `aicc_skill_inventory`에서 반환된 이 스킬 ID로 `aicc_skill_read`를 호출해 `SKILL.md` 전체, 이어 필요한 직접 참조만 읽는다. 다른 참조도 같은 스킬 안의 실제 경로를 쓴다.
- skill read가 없고 등록 workspace read만 있으면 그 경계에서 `korean-ui-quality/SKILL.md`와 필요한 참조를 읽는다. 이름·경로만 보고 읽었다고 주장하지 않는다. Web 컨테이너의 localhost·파일·폰트는 사용자 PC의 상태가 아니다.
- 연결 도구가 승인된 파일 편집·실행을 지원하면 그 경계에서 구현을 이어간다. 지원하지 않는 PC 작업은 관련 파일/화면·바꿀 내용·보존할 기능·완료 조건·미관찰 항목을 짧게 인계한다. 외부 대화로의 새 전송은 사용자가 승인한 경로만 쓴다.
- 기존 AICC 연결을 재사용한다. 로컬 본문 읽기/적용, ChatGPT에 별도로 스킬 등록/사용자 설치, 실제 스킬 사용은 별도 상태다. 새 계정·Work 전환·공급자 cache 수정이나 기존 권한 거절 우회로 배포하지 않는다.

ChatGPT에 등록된 스킬을 관리해야 하면 기존 `manage-chatgpt-skills`의 exact ID·백업·동기화 절차를 사용한다. 이 품질 스킬은 원격 설치·게시·자동 인계 권한을 추가하지 않는다.

## 글쓰기 기준과 연결

사용자의 글을 작성·교정할 때는 기존 owner-writing-style의 현재 정본과 해당 장르만 읽는다. 글쓰기 스킬은 저자의 어휘·호흡·격식·사실 보존을, 이 스킬은 화면의 명료한 행동 안내·표시와 전체 정보 접근을 맡는다. 자소서·면접·블로그·보고서에 UI의 해요체 예시나 짧은 버튼 문구를 전역 말투로 적용하지 않는다. 기존 사용자 문체 참조 도구도 필요할 때 재사용하며, 같은 문체 규칙을 새로 복제하지 않는다.
