이 문서에서 선택한 단계만 읽는다. 명령 예제의 기준 작업 폴더와 인라인 리소스 경로는 상위 스킬 루트다. Markdown 링크는 이 파일 위치를 기준으로 한다.

## 로컬 PC 종료 중에도 서버 실행이 필요한 경우

사용자가 로컬을 꺼도 계속 실행되길 요청하면 완료 조건을 서버의 수집→요약/처리→저장→예약 지속으로 잡는다. 웹 주소가 열림, 원격 로그인 화면, PC의 자막 전달, 사용자 답변 붙여넣기는 이 조건의 완료 증거가 아니다. 일반 요청까지 모두 서버 이전 요구로 확대하지 않는다.

- 실행, 수집 원본/인증, 모델 세션, 큐·잠금·미결 조정, 결과 저장, 예약/재기동의 실제 소유 호스트를 구분한다. PC의 SSH/VNC는 관리 진입점인지 상시 실행 의존성인지 별도로 적는다. 데이터가 PC에서 먼저 생성되어야 하면 서버 독립이 아니다.
- 기존 서버 서비스·저장소·스케줄러를 재사용한다. 메타데이터 동기화 예약을 모델 요약 예약으로 간주하지 않으며 요청 뒤 BackgroundTasks를 durable 작업 인계로 간주하지 않는다. 재시작 뒤 미결/불명 전송을 조정하는 경계가 있어야 한다.
- 웹 구독만 사용한다는 선택이면 developer-model API·유료 fallback·다른 provider로 바꾸지 않는다. 웹 예약/연결 기능이나 원격 브라우저의 지원 여부는 해당 공식 범위로 판단하고, 서버에서 브라우저를 실행할 수 있다는 기술적 사실만으로 서비스의 허용·로그인 지원을 보장하지 않는다.
- 인증 보안 거절은 자동 재시도/브라우저 전환/옵션 위장/세션 반입으로 해제하지 않는다. 지원 가능 경로가 미확정이면 서버 자동 처리 보장은 보류하고 조사·코드·배포·실제 무인 동작을 구분한다. 수동 전달은 보조 경로로 남기며 최종 서버 독립 해결로 대체하지 않는다.
- 새 검증은 현재 모델 정책과 사용자 요청 범위만 따른다. 서버 재시작·PC 종료·예약 실행을 실제 관측하지 않았다면 그 완료 조건은 미확인으로 유지한다.
