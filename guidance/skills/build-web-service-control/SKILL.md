# 자동화와 서비스를 웹에서 보고 제어하기

사용자는 자동화·서비스·트레이를 만들거나 확장할 때 PC와 폰의 웹에서 상태를 보고 조작하는 방식을 기본으로 원한다. 실행은 원래 로컬 PC나 서버가 맡고 웹은 같은 제어 계층을 사용한다. 이 선호는 새 공개 주소나 무제한 원격 실행 권한을 주지 않는다. 현재 요청에 해당하는 기능부터 구현하며 모든 기존 서비스를 한 번에 이전하지 않는다.

## 기존 기능부터 연결한다

- 가까운 PROJECT.md와 기존 서비스·트레이·웹 UI·작업 큐·기동 설정을 읽는다. 실제 실행 호스트, 소유자, 제어 API와 현재 지원 기능을 구분한다. 기존 어댑터와 원장을 재사용하며 웹 전용 실행기나 두 번째 스케줄러를 만들지 않는다.
- 트레이와 웹의 명령·권한·상태는 같은 백엔드에서 처리한다. 도메인이 다른 서비스는 얇은 어댑터로 연결한다. 이미 웹 화면이 있으면 그 화면을 확장한다. 작은 작업에 거대한 공통 플랫폼을 새로 만들지 않는다.
- AICC를 확장할 때만 [기존 구현 연결점](references/aicc.md)을 읽는다. 다른 프로젝트에 AICC 경로나 포트를 고정하지 않는다.
- AICC host 자기 세션·명시 대기는 components/host-control/README.md의 aicc_host_sessions/aicc_host_wait 계약을 따른다. HISTORY_UNPROVEN은 용량 부족으로 큐에 넣지 않고 원 request_id의 NOT_DISPATCHED를 조회해 원 client·host owner가 조정한다. 설치판 노출과 실제 호출 수락은 구분한다.
- 기존 Codex Desktop 대화의 터미널·트레이 메시지 전송에는 [공식 queue 연결](references/codex-queue.md)을 따른다. `exec resume`의 writer 잠금과 별개다. 접수·실제 turn·전체 업무 완료를 구분하고, 같은 operation의 불명 결과를 재전송하지 않는다. 무인 OCX 자동재개의 경로·quota 계약을 대신 충족한 것으로 처리하지 않는다.

## RDC 한도와 계정 전환

RDC 사용량 경고·계정 교체·연결 유지 요청은 [RDC 연속성 절차](references/rdc-continuity.md)를 읽는다. 커넥터의 실제 계정·잔여 비율과 PC 에이전트 계정은 별도로 확인한다. 지피티 커넥터 준비 없이 PC 계정만 자동 교체하지 않는다. 전환 중·완료 안내는 살아 있는 독립 제어 연결을 통해 전달하고, PC CONNECTED를 지피티 연결 완료로 보고하지 않는다.

## Web GPT와 다른 에이전트

Web GPT는 일반 Chat에서 기존 승인된 AICC 연결의 스킬 목록과 본문 읽기를 사용한다. 실제 노출된 호스트 도구와 grant로만 작업하며 웹 컨테이너를 사용자 PC로 보지 않는다. 지피티 스킬 업로드·사용자 설치·실제 호출은 별도 상태다. 이 스킬 본문을 읽을 수 있다는 사실이 원격 관리 권한이나 지피티 스킬 설치 완료를 뜻하지 않는다.

## Termius 터미널 메뉴와 다시 열기

폰의 SSH/psmux 터미널 선택·닫힌 터미널 재개·Windows 자동 시작을 다룰 때는 [폰 터미널 절차](references/phone-terminal.md)를 사용한다. 기존 SSH 서비스를 재사용하고 메뉴/기록 자동 시작과 코덱스 작업 재개를 구분한다.
