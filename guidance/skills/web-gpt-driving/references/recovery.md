# 선택 대화의 복구

각 조치는 정확한 대화·응답 ID와 원래 전송 intent에 결속한다. 진행 중인 외부 쓰기·결제·민감 승인이 보이면 HOLD한다. 숨겨진 외부 작업의 완료를 UI만으로 증명하지 않는다.

행동 직전에 현재 상태를 다시 분류한다. 누적 장애 타이머보다 현재 상태가 우선한다. 연결 끊김이 timeout·생성 종료·입력 가능으로 전이했으면 이미 끝난 응답을 중지하지 않고 아래 시간 초과 절차를 따른다. 20분 경과 자체는 Stop 실행 조건이 아니다.

## 시간 초과

실제 timeout 문구, 생성 종료, 입력 가능한 빈 composer를 함께 확인한다. 원래 요청의 제출·최종 결과부터 회수한다. 그 상태가 확정됐고 재개가 승인된 대상에만 `이어서 작업해.`를 한 번 보낸다. Retry 버튼이나 새 대화로 원요청을 복제하지 않는다.

## 연결 끊김과 정체

- 최초 관측 UTC, exact 응답 ID, 마지막 진행과 생성 상태를 기록한다. 기록이 없으면 과거 정체 시간을 추정하지 않는다.
- 초안과 불명 전송이 없을 때 해당 탭만 새로고침 한 번, 필요한 경우 30초 뒤 재관측한다. 정상 회복이나 새 응답이면 장애 시계를 초기화한다.
- 렌더 wrapper ID와 실제 메시지 ID를 구분한다. data-dil-message-id가 새로고침 뒤 바뀐 관측만으로 새 응답 시작이나 같은 응답의 정체 지속을 확정하지 않는다. 안정 ID가 확인되지 않으면 정확한 대화 URL·원래 user intent·현재 응답 내용과 생성 상태를 함께 보존하고 ID 결속 신뢰도를 미확인으로 남긴다. 해당 타이머만으로 중지하지 않으며 읽기 회수와 정상 완료 확인은 계속할 수 있다.
- 중지 기준은 사용자가 승인한 해당 대상의 설정을 따른다. 기존 감독기의 30분 기준을 임의로 20분으로 바꾸지 않는다. 20분 정책을 별도 승인했더라도 구현·배포 전에는 현재 실행기로 지원한다고 말하지 않는다.
- 같은 응답이 기준 시간 동안 정체됐고 실제 중지 버튼이 있을 때만 한 번 중지한다. 중지 전이와 빈 composer를 확인한 뒤 승인된 고정 문구를 한 번 보낸다. 별도 문구가 승인된 경우: `작업이 지연되어서 내가 중지시켰어. 중단 지점부터 작업을 재개해`.
- stop·send 응답이 불명이면 해당 intent를 보존하고 재시도하지 않는다. 외부 결과가 UNKNOWN이면 응답 재개와 외부 작업 완료를 구분한다.

## 반복 실패와 인계

기존 대화의 정본·완료 응답을 먼저 회수한다. 새 대화 생성이 사용자의 승인 범위에 포함될 때만 같은 프로젝트의 후속 대화 하나에 목표·결정·정본·변경·미확인·HOLD·다음 행동을 전달하고 URL을 결속한다. 원래 대화와 사용자 초안을 보존한다. 새 대화·계정·로그인·경로 변경으로 보안 거절이나 한도를 우회하지 않는다.

## 읽기 회수 뒤 행동 취소

최신 답변 영역을 현재 viewport에 포함해 읽은 뒤 실제 오류·본문·생성 상태를 다시 구분한다. 오류가 사라지고 본문을 회수했으면 준비했던 새로고침·재생성·재전송을 실행하지 않는다. 제목이나 과거 완료 버튼, 전체 대화 skill badge만으로 최신 답변 완료·최신 skill 호출을 판정하지 않는다. 회수한 메타데이터의 집계 기록은 단일 writer가 직렬 갱신하며 기록 누락만으로 외부 요청을 다시 보내지 않는다.
