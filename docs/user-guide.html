AICC · OCX · Codex 쉬운 사용 설명서

평소 작업은 Codex, 연결·계정 관리는 AICC에서 합니다. 터미널에서는 OCX와 Native를 명시적으로 고를 수 있습니다. Desktop은 현재 설정된 연결을 사용합니다. 이 문서는 사용법의 입구입니다. 현재 설치의 완료·보류 상태는 작업 기록에서 확인합니다. 문서에 적힌 사용법과 실제로 검증된 범위는 다를 수 있습니다.

1. 세 가지만 기억하기

명령은 한 줄씩 실행합니다. 앞 명령이 끝난 뒤 다음 명령을 입력하세요. doctor는 진단이고 repair는 변경을 포함합니다. 결과에 보류가 나오면 아래 문제별 안내를 봅니다.

2. 각각 무엇인가요?

OCX / OpenCodex 모델 요청과 계정 풀을 연결하는 중계기 기본 모델의 계정 전환과 한도 차단을 담당합니다.
웹 GPT 연결 Codex의 요청을 로그인된 ChatGPT 웹에 보내는 연결 전용 연결을 설치·검증한 뒤 사용합니다.
AICC Workspace 앱 ChatGPT 웹에서 허용된 로컬 폴더를 사용하는 연결 웹에서 로컬 파일을 읽거나 고칠 때 사용합니다.

Codex와 웹 GPT 연결은 작업 방향이 두 가지입니다.

  • Codex → 웹: Codex에서 웹 모델을 선택하고, 웹 GPT가 현재 작업의 도구를 사용합니다.
  • 웹 → 로컬: ChatGPT에서 AICC Workspace 앱을 선택하고, 허용된 폴더의 도구를 사용합니다.

한쪽 성공이 다른 쪽 성공을 보장하지 않습니다. MCP는 도구 연결입니다. MCP가 연결됐다고 모델 목록까지 자동으로 추가되는 것은 아닙니다.

3. 평소 사용하는 방법

Codex에서 작업하기

  1. Codex Desktop에서 작업할 프로젝트와 대화를 선택합니다. 터미널에서는 작업 폴더에서 codex를 실행합니다.
  2. 원하는 결과를 말합니다. 예: “이 오류를 고치고 실행해서 확인해줘.”
  3. 끝났다는 답에서 변경 파일, 실제 검증 결과, 남은 사항을 확인합니다.
  4. 복잡한 작업을 이어받을 때는 기존 대화 링크와 context/PROJECT.md를 함께 알려줍니다.

명령은 codex, 다른 연결은 명시 선택

command-route-r2는 소스 작성 단계입니다. 이번에는 HOME 설정·설치판·Desktop을 바꾸지 않았습니다. root의 정상 적용 여부는 작업 기록에서 확인합니다.

목적명령
평소 작업 · 공유 HOME, OCX10100 기본 목표codex
독립 정비 · Native V2 profilecodex -p native
Web17841 · 별도 Web catalog profilecodex -p aicc-webgpt
명시 OCX 계정 · 기존 보호를 유지하는 호환 실행aicc codex ocx --account 1
OCX 서비스 관리ocx status

별도 선택하지 않은 모델·추론·승인·sandbox·personality·skills/plugins는 사용자 설정을 상속합니다. 필요한 모델만 --model gpt-6.1-sol로 명시합니다. 새 HOME이나 로그인을 만들지 않고, 실패한 명령을 다른 경로로 자동 재전송하지 않습니다. Native는 독립 정비에만 사용합니다.

트레이 CLI 탭에서 폴더를 고르고 모델은 비워 두고 추론은 사용자 설정 상속으로 둡니다. 명시 계정만 호환 실행기를 사용하며 Native 선택은 독립 정비용 profile입니다. 필요한 모델과 medium/high만 명시 선택합니다. 터미널 열기와 실제 모델 접수는 별개이며 이번 트레이 빌드·설치·화면 확인은 미실행입니다.

일반 지피티의 aicc_codex_cli_start/status는 기존 owner binding의 route/model/effort를 명시합니다. 로컬 기본값 변경은 원격 권한 확장이 아닙니다. 적용·복귀는 CLI 운영 안내를 따릅니다.

AICC 상태 창 읽기

Windows 오른쪽 아래의 **숨겨진 아이콘(∧)**에서 파란색 A 아이콘을 누르면 작은 상태 창이 열립니다. 창 밖을 누르면 닫힙니다.

  • 맨 위에서 AICC, OCX, Web GPT의 연결 상태를 확인합니다.
  • 각 OCX 계정의 사용 상태, 5시간·주간 남은 한도와 초기화 시각을 봅니다. 시각은 한국 시간입니다.
  • 한도를 넘은 계정은 한도 차단, 사용량을 확인하지 못한 계정은 확인 필요로 표시합니다.
  • 1분마다 갱신합니다. 아이콘을 오른쪽 클릭하면 즉시 새로고침, 관리 화면, 이 설명서를 열 수 있습니다.
  • 조회 실패나 한도 미확인은 정상으로 표시하지 않습니다. 아이콘을 종료해도 연결 서비스는 계속 실행됩니다.

AICC 연결은 창 없는 예약 작업으로 실행됩니다. 상태 확인을 위해 터미널을 열어둘 필요가 없습니다.

설치본에서 지원하면 다음 명령으로 관리 화면을 엽니다.

aicc open

화면이 열려도 모든 연결이 정상이라는 뜻은 아닙니다. 문제가 있으면 aicc doctor 결과를 먼저 봅니다. 화면을 열지 않고도 진단과 복구 명령을 사용할 수 있습니다.

ChatGPT에서 로컬 파일 사용하기

  1. 사용할 ChatGPT 계정과 워크스페이스를 확인합니다.
  2. 등록된 AICC Workspace 앱을 선택합니다.
  3. 전체 프로젝트를 사용할 때는 projects를 한 번 엽니다. 개별 프로젝트는 그 안의 경로로 선택합니다.
  4. 읽기 작업은 읽기 모드, 편집은 쓰기 모드로 구분합니다.
  5. 바꾼 내용을 다시 읽어 확인하고 작업 공간을 닫습니다.

예: “AICC에서 projects를 읽기 모드로 열고 자동매매와 커리어 프로젝트를 확인해줘.” projects 안의 기존·새 프로젝트는 각각 등록하거나 접근을 다시 허용할 필요가 없습니다. 파일 수정·명령 실행과 비밀·인증 자료의 보호는 별도로 적용됩니다.

4. 문제가 생겼을 때

먼저 아래 두 명령을 순서대로 사용합니다.

aicc doctor
aicc repair
증상 또는 결과 다음 행동
ok, ready 해당 검사 항목이 정상입니다. 원하는 작업도 실제로 확인합니다.
warning, degraded 경고 내용을 봅니다. 경고만 보고 초기화하거나 삭제하지 않습니다.
NEEDS_FOREGROUND, 관리자 실행 필요 다음 절의 관리자 Sandbox 복구를 사용합니다.
Session terminated AICC 연결 상태를 검사합니다. 이미 전송한 쓰기 요청은 결과부터 확인합니다.
웹 답변이 늦거나 시간 초과 원래 대화와 실제 파일 결과를 확인합니다. 같은 요청을 무작정 다시 보내지 않습니다.
모델 목록이 비어 있음 Native / 웹 / OCX 중 어느 경로인지 확인합니다. 정상 Native 설정을 덮어쓰지 않습니다.
오래된 대화만 실패 그 대화에 저장된 provider와 현재 연결 상태를 확인합니다. 대화 기록은 보존합니다.
접근 승인 필요 필요한 폴더만 로컬 접근 화면에서 승인합니다. 연결 장애로 단정하지 않습니다.

AICC가 종료됐을 때

기존 Windows 자동 복구가 설치된 환경은 같은 예약 작업으로 재기동을 시도합니다. 약 1분 뒤 aicc doctor로 다시 확인합니다. 시간만 지났다고 복구된 것으로 판단하지 않습니다. 계속 실패하면 aicc repair를 사용합니다. 실행 중인 다른 작업이 있으면 안전을 위해 복구가 보류될 수 있습니다.

진단 결과를 자세히 보기

aicc doctor --json

이 결과와 증상을 Codex에 알려주면 됩니다. 로그인 파일, 토큰, 쿠키 원문을 붙여 넣을 필요는 없습니다.

5. Windows Sandbox와 관리자 권한

Sandbox는 Codex 명령이 접근할 수 있는 범위를 제한하는 Windows 실행 환경입니다. elevated 방식의 설정에는 관리자 승인이 필요할 수 있습니다. 이 말은 평소 Codex 전체를 항상 관리자로 실행해야 한다는 뜻은 아닙니다.

가장 간단한 복구

  1. Windows 시작 메뉴에서 PowerShell을 찾습니다.
  2. 관리자 권한으로 실행을 선택하고 Windows 확인창을 승인합니다.
  3. 다음 명령을 실행합니다.
codex-repair --sandbox
  1. 완료 후 aicc doctor를 실행합니다. sandbox.provisioning과 sandbox.readiness가 함께 정상인지 확인합니다.
  2. 다음 안전한 재실행 때 Desktop의 설치 미완료 배너가 사라졌는지도 확인합니다.

짧은 명령을 찾지 못하는 경우에만 공식 fallback을 사용합니다.

codex sandbox setup --elevated --current-user

Codex를 관리자로 열면 직접 복구해줄 수 있나요?

실제 명령 실행 프로세스가 관리자 권한이면 가능합니다. 앱의 표시만으로 판단하지 않습니다. 이미 실행 중인 앱이 새 창 요청을 받거나 실행 도구가 별도 프로세스를 사용하면 권한이 전달되지 않을 수 있습니다. Codex에 “현재 터미널의 관리자 권한부터 확인하고 Sandbox를 복구해줘”라고 요청하세요. 관리자 권한이어도 Windows 정책이나 폴더 잠금이 원인이면 추가 진단이 필요합니다.

Desktop을 관리자로 여는 순서는 다음과 같습니다.

  1. 작업을 저장하고 Codex Desktop을 완전히 종료합니다. 창만 닫으면 기존 프로세스가 남을 수 있습니다.
  2. 시작 메뉴에서 Codex를 찾고 마우스 오른쪽 버튼 → 관리자 권한으로 실행을 선택합니다.
  3. Windows 확인창을 승인하고 대화를 다시 엽니다.
  4. “실제 명령 실행 프로세스가 관리자인지 확인해줘”라고 요청합니다. 터미널 탭은 앱과 권한이 다를 수 있습니다.

확실한 CLI 방법은 관리자 PowerShell을 먼저 열고 codex를 실행하는 것입니다. 다른 관리자 계정의 비밀번호로 실행하면 사용자 폴더와 로그인 환경이 달라질 수 있으므로 같은 Windows 사용자를 사용합니다. 이미 codex-repair --sandbox가 PASS이고 elevated · complete · ready라면 다시 설정할 필요가 없습니다.

관리자 PowerShell에서 공식 codex를 실행하는 방법도 있습니다. 이 방법은 새 CLI 대화입니다. 기존 Desktop 대화 링크를 주고 작업 기록부터 읽어 이어받도록 합니다. UAC 확인은 사용자가 직접 승인합니다.

설정의 approval = never 또는 “전체 접근”은 Windows 관리자 권한을 만들어주지 않습니다. 복구 후에는 일반 권한으로 돌아와 평소 작업을 합니다.

공식 안내: OpenAI Windows Sandbox.

6. OCX 사용과 계정 전환

OCX를 의도적으로 꺼둔 상태는 장애가 아닙니다. 일반 aicc repair는 OCX를 자동으로 켜지 않습니다. 현재 기본 모델은 OCX를 거치므로 OCX를 끄면 요청도 멈춥니다. 한도 보호를 우회해 공식 연결로 자동 대체하지 않습니다. 아래 명령으로 기존 연결을 복구합니다. 다시 사용하기로 결정했을 때만 기존 복구 명령을 사용합니다.

aicc-ocx-recover -Open

이 명령은 기존 OCX 연결을 검사하고 필요하면 기존 서비스를 켜며 대시보드를 엽니다. 화면이 열리는 것, 계정이 로그인된 것, 모델 응답이 오는 것은 각각 확인해야 합니다.

평소 OCX 주소는 http://localhost:10100 하나입니다. PC 화면에서 관리한 계정·provider·모델·설정은 A1 서버가 소유합니다. 내부 연결 포트 10102는 직접 열 필요가 없습니다. 연결 코드 화면이 나오면 A1에서 발급한 일회용 코드를 붙여 넣습니다. 모델 요청용 키와 관리 연결 코드는 다릅니다. PowerShell에서 aicc-ocx-hub -Action pair를 실행하고 결과의 grant 값을 연결 코드 칸에 붙여 넣습니다. 직접 코드를 붙여 넣기 싫다면 aicc-ocx-open을 실행하세요. 전용 Chrome 창을 열고 공식 일회용 인증을 대신 진행합니다. 평소 Chrome 로그인과 탭은 건드리지 않습니다. 이 코드는 다른 사람에게 보내거나 파일에 저장하지 않습니다. 새 탭과 새로고침에는 다시 연결할 수 있습니다. 코드 유효기간은 5분, 인증된 관리 세션은 마지막 사용 후 12시간입니다. 로그인 정보를 영구 저장하거나 관리자 토큰을 넣어 이 절차를 생략하지 않습니다.

계정 전환을 믿어도 되는 조건

현재 A1 실행본은 2.77.0-aicc.windows.1입니다. 요청마다 사용량을 새로 확인하고, 5시간 95% 사용 또는 주간 98% 사용(2% 남음) 계정의 전송을 차단합니다. 사용 가능한 다른 계정으로 전환하며, 대체 계정이 없거나 조회가 실패하면 요청을 멈춥니다. PC 화면의 단일 임계값만으로 서버 차단 여부를 판단하지 않습니다. aicc-ocx-policy -Action status로 실제 서버의 두 기준을 확인합니다. 설정값만 보이면 충분하지 않습니다. 아래 네 가지가 필요합니다.

  1. 현재 사용 중인 실제 계정이 확인됩니다.
  2. 사용량이 최신 숫자로 조회됩니다. 비어 있으면 정상 판정하지 않습니다.
  3. 다음 계정이 로그인 상태이며 사용 가능한 한도가 있습니다.
  4. 경계에 도달한 시험 또는 안전한 대체 시험에서 실제 전환을 확인합니다.

Windows가 OCX client이고 계정 소유자가 별도 hub인 환경에서는 로컬 계정 목록만 믿지 않습니다. 기존 hub 조회 명령이 설치됐다면 읽기 전용 상태를 확인합니다.

aicc-ocx-hub -Action status

refresh는 계정 사용량을 갱신하는 별도 작업입니다. pause, resume, 전환과 로그인은 상태 조회와 다릅니다. status는 캐시를 읽으며 조회 시각이 보장되지 않습니다. 빈 사용량은 0%가 아닙니다. 최신 숫자는 aicc-ocx-hub -Action refresh로 확인합니다. 95% 규칙은 OCX를 거치는 요청에 적용됩니다. 현재 Desktop의 기본 모델도 OCX를 거칩니다. 별도로 공식 OpenAI에 직접 연결한 실행에는 이 보호가 적용되지 않습니다. 파일을 업로드한 대화는 파일 보호 규칙 때문에 전환이 제한될 수 있습니다. 계정별 임계값·고정·우선순위·일시정지·쿨다운도 함께 확인합니다. 계정 번호는 목록 순서로 추측하지 않습니다. 실제 계정명과 로그인을 확인합니다.

정책 원복은 aicc-ocx-policy -Action rollback입니다. 서버에 진행 중인 요청이 있으면 멈추지 않고 거절합니다. 원래 실행본·계정·로그인·기록은 보존합니다. 자세한 설명은 OCX 운영과 복구를 봅니다.

7. 웹 모델 선택과 양방향 작업

목표는 Desktop 모델 목록에서 웹 모델을 선택하고 현재 Codex 작업을 그대로 진행하는 것입니다. 이 동작에는 모델 provider, 목록, 웹 로그인, 도구 연결이 모두 필요합니다.

완료는 다음 순서로 확인합니다.

  1. 기존 Codex 로그인과 기록을 유지합니다.
  2. 새 연결을 별도 시험으로 준비합니다.
  3. 실제 Desktop 목록에서 웹 모델을 선택합니다.
  4. 임시 파일을 읽고 수정한 다음 다시 읽어 확인합니다.
  5. 같은 대화를 새 프로세스에서 이어갑니다.
  6. 작업 중단, 스킬과 플러그인도 각각 확인합니다.

목록 조회나 작은 답변만 성공한 상태는 전체 완료가 아닙니다. Desktop 적용이 미완료라면 모델 이름만 보고 연결됐다고 생각하지 않습니다. 2026-10-04 사용자가 Desktop에 웹 모델이 표시됨을 확인했습니다. 현재 목록에는 **1번(demo-ownerd28)**과 **2번(wntlrqpdj)**이 각각 임시·저장 대화와 네 가지 추론 수준으로 표시됩니다. 모두 16개입니다. 두 이름은 실제 웹 로그인으로 확인했습니다. 2번 모델은 이름에 계정 2가 붙습니다. 해당 계정이 연결되지 않으면 오류를 내고 멈춥니다.

웹 모델이 숨겨지지 않도록 model_catalog_json 설정을 연결의 정식 원복 기록에 넣었습니다. 웹 연결을 해제하면 이전 모델 목록 설정도 복원됩니다. 연결 중에는 HTTP 스트리밍을 사용하므로 진단에 WebSocket 경고가 나올 수 있습니다. 실제 Native·웹 응답은 별도 시험으로 확인합니다.

기본 GPT-6.1 Sol은 기존 Codex 연결에서 OCX 계정 풀을 거칩니다. 2026-10-04 22:17 KST에 기존 대화 기록을 이용한 실제 응답을 확인했고, 로그인·대화·전역 설정은 보존했습니다. 웹 모델을 선택하면 표시된 계정의 Web GPT로 연결됩니다. 웹 모델의 한도와 OCX 한도는 별개입니다. 웹 대화를 바로 만드는 명령도 준비했습니다.

aicc-web-task -Prompt '진행할 작업'

결과의 thread_id를 복사해 같은 웹 대화를 이어갑니다.

aicc-web-task -Action resume -ThreadId '대화 ID' -Prompt '이어서 할 작업'

이 명령은 처음 고른 웹 모델과 작업 폴더를 유지합니다. 연결이 끊기면 오류를 내고 멈춥니다. Native로 자동 대체하지 않습니다. codex exec resume에서 모델을 생략하면 Native 기본 모델로 바뀔 수 있으므로 웹 대화에는 위 명령을 사용합니다. 같은 대화를 Desktop과 터미널에서 동시에 실행하지 않습니다. Desktop이 대화의 실행 권한을 가지고 있으면 터미널 이어쓰기는 거절됩니다. 강제로 프로세스나 실행 잠금을 지우지 않습니다.

새 웹 대화 생성과 새 프로세스에서 같은 웹 모델·원래 작업 폴더로 이어쓰기를 실제로 확인했고, Desktop에서도 저장된 답변을 읽었습니다. 2026-10-04 사용자가 Desktop 모델 목록에 웹 모델이 표시됨을 확인했습니다. 모델 목록 표시와 실제 응답 성공은 각각 확인합니다.

Desktop의 작업 전달 오류를 수정해 실제 이어쓰기에서 시험 파일 생성·다시 읽기·최종 답변을 확인했습니다. 이전 실패 요청은 다시 보내지 않았습니다. 공식 create_thread로 웹 모델 시험 대화도 만들었습니다.

현재 웹 실행본은 2.0.0-aicc.36입니다. 진행 중인 요청이 없는 때 교체했고, Native 설정은 보존했습니다. 계정 2의 실제 파일 생성·다시 읽기와 같은 대화 이어쓰기를 확인했습니다. Desktop의 작업 전달도 실제 파일 작업을 통과했습니다. Desktop에서 전체 접근으로 시작한 웹 대화는 작업 폴더만 읽는 Windows 명령 실행을 확보하지 못해 제한을 유지합니다. 이 대화에는 하위 에이전트 도구도 노출되지 않았습니다. 별도로 권한을 제한한 웹 대화에서 자식 생성은 확인했지만, 정확한 답변 전달 시험은 통과하지 못해 에이전트 사용은 미완료로 남겼습니다. Native 대화에서 웹 에이전트로 바로 넘기는 경로는 암호화 형식 차이 때문에 지원되지 않습니다. 새 시험 대화에서 1번과 2번의 실제 응답을 확인했습니다. 불필요한 화면·페이지 저장을 줄였고, 관련 검사 211개를 통과했습니다. 연결 확인과 답변 완료 확인은 유지합니다. 세 준비 구간은 한 번의 비교에서 5.4초에서 2.4초로 줄었지만, 전체 답변은 32초에서 39초로 늘었습니다. 전체 속도가 빨라졌다고 판단하지 않습니다. 2번의 새 대화 답변은 약 25초였습니다. 하위 에이전트 시험은 도구를 사용할 수 없다는 답변으로 끝났고 실제 자식이 생성되지 않아 미완료입니다.

진행 상태는 작업 기록, 상세 연결은 웹 GPT와 복구를 봅니다.

8. 계정 변경과 기존 대화 이어가기

Codex 로그인 계정, ChatGPT 웹 계정, OCX 계정 풀은 서로 다릅니다. 하나를 바꿨다고 나머지도 바뀌지는 않습니다. 계정 변경 뒤에는 aicc doctor로 Native 연결과 Sandbox를 다시 확인합니다. 전송 중인 작업은 결과를 확인한 뒤 변경합니다.

기존 OCX 대화는 OCX provider를 기억할 수 있습니다. OCX가 꺼져 있으면 그 대화가 실패할 수 있습니다. 그럴 때는 새 Native 대화에서 이전 링크와 작업 기록을 주고 이어갑니다. 원래 대화를 삭제하지 않습니다.

ocx recover-history --ocx-compaction은 조건을 확인한 개별 압축 기록 복구입니다. 전체 대화를 Native로 바꾸거나 DB 목록을 정리하는 명령이 아닙니다. 전문가가 백업과 적용 조건을 확인할 때만 사용합니다.

10. 백업과 업데이트

복구 전에 바꿀 설정과 실행본을 백업합니다. 변경 뒤에는 연결과 실제 작업을 다시 검사합니다. 공식 Codex, OCX, 웹 연결, AICC는 각각 업데이트하고 검증합니다. 한 번에 전부 바꾸지 않습니다. 10100 화면의 업데이트는 A1 서버 OCX를 대상으로 합니다. PC OCX까지 업데이트됐다는 뜻은 아닙니다. 현재 A1에는 두 창의 전환 기준과 요청 전 차단을 적용한 2.77.0-aicc.windows.1 실행본이 있습니다. 화면의 공식 업데이트 버튼은 정책 보호 안내와 함께 차단됩니다. 업데이트 확인은 aicc-ocx-update -Check를 사용합니다. 새 공식 버전의 코드가 확인되기 전에는 자동으로 덮어쓰지 않습니다. PC 서비스와 터미널 ocx는 공식 2.77.0, A1은 이를 바탕으로 한 정책 버전입니다. 과거 설치본은 삭제하지 않았습니다.

OCX의 두 실행본을 함께 확인·갱신할 때는 aicc-ocx-update를 사용합니다. 확인만 할 때는 aicc-ocx-update -Check입니다. 최신 버전이면 재설치·재시작하지 않습니다. 새 버전이면 소프트웨어 백업 후 서버, PC 순서로 공식 updater를 사용합니다. OCX가 의도적으로 꺼져 있거나 작업 중이면 갱신을 보류합니다. 실패 시 완전히 멈춘 것으로 확인된 실행본만 코드 백업으로 복원합니다. 소유자가 불명확하거나 살아 있으면 강제 종료하지 않습니다. 서버와 PC 중 일부만 바뀌면 결과를 따로 확인합니다. 2026-10-05에 PC와 A1의 2.77.0 설치·실행 및 실제 응답을 확인했습니다. aicc-ocx-update -WaitForIdleSeconds 300은 최대 5분 동안 작업 종료를 기다립니다. 마지막 설정 검사에서 변경이 발견되면 실행 버전을 따로 확인하고, 기존 설정을 자동으로 덮어쓰지 않습니다. 복구 명령이 정상 설정을 덮어쓰거나 데이터 삭제를 제안하면 적용 전에 정확한 범위를 확인합니다.

다음은 일반 장애 복구용 삭제 대상이 아닙니다.

  • Codex와 OCX 로그인 정보, auth.json, 계정 저장소
  • .codex 전체, 기존 대화와 rollout 파일
  • SQLite DB, provider 정의
  • AICC 등록 폴더와 기존 접근 승인

이전 실행본을 남기는 것은 로그인 상태를 과거로 되돌리는 것과 다릅니다. 업데이트 상세는 호환성과 업데이트를 봅니다.

11. 남은 작업과 필요한 사용자 도움

현재 완료 상태의 정본은 작업 기록입니다. 이 설명서는 실시간 상태판이 아닙니다. 사용자에게 필요한 도움은 문제가 실제로 막힌 단계에서만 요청합니다.

단계 사용자가 도울 수 있는 일 완료 확인
관리자 Sandbox 복구 관리자 PowerShell에서 짧은 복구 명령 실행, 또는 관리자 실행 환경 제공 provisioning 정상 + readiness 정상
Desktop 재실행과 계정 전환 작업 결과 저장 뒤 필요한 재실행·로그인 승인 배너 재발 없음 + Native 실제 응답
웹의 도구 승인 해당 시험 대화의 정확한 도구 승인 요청 확인 최종 결과, 출력, 닫기 확인
Local Source 접근 시험에 필요한 폴더만 선택·승인 실제 읽기·검색·닫기
로그인 또는 MFA 서비스가 요구할 때 승인 실제 로그인 계정 확인

일반 코드 수정, 문서 정리, 안전한 임시 파일 시험과 진단은 Codex가 진행합니다. 한 번의 관리자 실행으로 웹 로그인이나 앱 접근 승인이 자동으로 해결되지는 않습니다.
