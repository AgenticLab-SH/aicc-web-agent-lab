# AICC 공개 작업 범위

## 작업 위치와 실행

브랜치 **aicc-source-20261122**의 public/, src/, components/android-client/, tools/platform/windows/, contracts/, test/에 최신 개발 소스와 계약을 제공합니다. examples/lab-server.mjs가 실제 화면의 합성 API를 제공하고 examples/lab-server.test.mjs가 권한·단회 확인을 검사합니다. 운영 초기화와 계정 도구 실행은 승인된 소유자 환경에서 수행합니다.

- 빠른 확인은 **npm ci --ignore-scripts**, **npm run check:lab**, **npm test**, **npm run preview**를 사용합니다. Windows 추가 검사는 **npm run verify:windows**입니다.
- 브라우저에서 /mobile.html#overview, /mobile.html#apps, /mobile.html#tools, /mobile.html#accounts, /install.html을 확인합니다. ‘연결 진단 (모의)’는 미리보기 → 단회 확인 → 원 결과 읽기를 재현합니다. 예시 demo-unconfirmed 작업은 조회할 때 UNKNOWN을 반환합니다. 연결 실패 시 이전 표시를 유지하는 동작을 점검하세요.
- Android 디버그 빌드는 JDK 21·Gradle 8.14·Android SDK 36으로 **gradle -p components/android-client :app:assembleDebug**를 실행합니다. 기본 주소는 예약 도메인 예시입니다. 앱 서명, 웹 인증과 Windows의 PC 복구는 제품이 운영하는 별도 경계입니다.
- 원 서버와 Windows용 운영 도구의 코드와 명세를 읽어 계약을 이해할 수 있습니다. 실기기·서명·외부 연동 검증에 필요한 원장과 비밀은 이 작업본과 분리돼 있습니다.

## 제공 대체물과 제외

- 합성 앱·계정·현황과 example.invalid 가상 주소를 사용합니다. 공개 미리보기의 합성 항목에는 실제 대상의 식별자를 넣지 않습니다. 홈·로컬 저장·신뢰·키·서명은 복사하지 않았습니다. 배포 APK 경로는 모의 환경에서 404이며 버전 JSON만 합성 예시입니다.
- 운영 및 개인 주소는 예시 주소로 바꿨습니다. 실사용 운영 영수증·백업·사용자 설정·유출 위험이 있는 자료·전용 어댑터와 원 유저 상태는 제외했습니다. 비공개 issuer 모듈은 외부 호출 없이 거절하는 인터페이스를 제공합니다.
- OpenCodex는 별도 공개 업스트림입니다. 이 브랜치에는 외부 업스트림 소스를 함께 저장하지 않습니다. 공급자 설정이 필요하면 [기존 공개 모델 어댑터 계약](../contracts/model-adapter/)을 사용하세요.
- 공개 저장소의 main과 web-design-v1에는 기존 디자인 자료가 있습니다. 이 브랜치는 AICC 전용 작업 공간입니다.

## 최신 ZIP 인수

기존 작업 브랜치의 4104812b5a8ef092e028348d94361e99923cd5e2를 기준으로 한 전체 제어 화면을 인수했습니다. 첫 화면에 앱 목록 상태에 따른 다음 행동을 표시합니다. 설치 안내는 기기에서 완료하는 단계와 다운로드 버전 정보를 구분하며, 합성 환경에서는 APK 다운로드 동작을 표시하지 않습니다. [인수 기록](../HANDOFF.md)에 받은 범위와 검증을 기록했습니다.

## 이번 작업 순서

목표는 AICC를 열고 몇 초 안에 현재 상태와 다음 행동을 찾게 하는 것이다. 모바일과 PC는 같은 화면을 쓰고, Windows 트레이는 이 화면을 여는 진입점과 로컬 복구 수단으로 둔다.

1. **기준 화면 실행.** 받은 ZIP 또는 Git 커밋을 기록하고 [제품 명세](dashboard-product-spec.md)를 읽는다. Node.js 22 이상에서 `npm ci --ignore-scripts`, `npm run check:lab`, `npm test`, `npm run preview` 순으로 실행한다. `http://127.0.0.1:4173/mobile.html#overview`와 내 앱·도구·설치 페이지에서 현재 이동 경로를 확인한다.
2. **첫 화면과 주요 이동.** 업데이트 시각은 맨 위에 유지한다. 첫 화면에서 전체 개발 현황, 내 앱, 설치·업데이트, 공통 도구에 바로 갈 수 있게 한다. 현재 선택과 화면 제목이 분명해야 하고, 이미 있는 안내와 동작은 한 번씩만 보여 준다.
3. **내 앱과 설치.** 최근 사용과 검색을 활용해 앱을 찾게 한다. 웹에서 열기, Android 설치·업데이트, PC 전용, 주소 미등록을 구분하고 각각 가능한 버튼을 보여 준다. 합성 사례로 열기와 설치 안내를 확인한다. 배포 파일 정보와 기기에 설치된 상태를 따로 표시한다.
4. **공통 도구와 트레이 연결.** 기존 제어 화면을 앱의 용어와 디자인에 맞춘다. PC 전용 동작은 해당 메뉴와 이유를 표시한다. 트레이에서 열 URL과 복구 진입은 `HANDOFF.md`에 적는다. 실제 Windows 설치나 네이티브 트레이 UI 변경 없이 웹 화면과 연결 명세를 반환한다.
5. **실패와 기존 계약 검증.** 합성 API만 사용한다. 연결 만료·빈 목록·조회 실패·마지막 목록 유지, ‘연결 진단 (모의)’의 미리보기→단회 확인→원 결과 조회, `demo-unconfirmed`의 불명 상태를 확인한다. 320·360·768px와 데스크톱, 큰 글자와 키보드에서 조작하고 콘솔 오류나 가로 넘침을 확인한다. 로그인·권한 범위와 원 결과 조회 계약을 유지한다.
6. **반환.** `aicc-control-web-result.zip` 또는 패치와 `HANDOFF.md`를 반환한다. 기준 커밋, 변경 파일, 재실행 명령, 화면 캡처, 수행한 검사와 미실행 범위를 적는다. 환경 제약으로 못 한 단계는 명시하고 가능한 다음 단계를 계속한다.

변경 범위는 공개 웹 UI, 필요한 합성 API·테스트와 인수 문서다. 실제 계정·기기·서명·운영 주소·실행 권한은 사용하지 않는다. 계정이나 큐의 실제 상태 변경, 외부 배포는 이 작업의 범위 밖이다.

CI 정의 원형은 examples/ci/의 참고 파일로 제공합니다. 공개 작업본 브랜치에는 push로 실행되는 배포 구성이 없습니다.
