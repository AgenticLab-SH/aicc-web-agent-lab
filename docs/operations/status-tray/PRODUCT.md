표시 숫자는 원장에 기록된 실행 상태의 건수다.

- `대기`: 일시 중지(`paused`)로 기록된 건수.
- `완료`: 큐 실행 완료(`completed`)로 기록된 건수.
- `취소`: 큐 실행 취소(`cancelled`)로 기록된 건수.

이 집계만으로 자동 발신 성공이나 프로젝트 전체 완료를 증명할 수 없다. 요청 전송·접수·소스 변경·실제 적용과 동작은 각각 별도 근거로 확인한다. 상태 조회에 실패하면 숫자를 추측하지 않고 `개발 큐 확인 필요`로 표시한다.

## 휴대폰 사용한도와 Slack 전체 현황

## Tailscale을 끈 PC 로컬 적용
PC의 loopback 주소 사용과 화면 배포에는 Tailscale이 필요하지 않다. 기존 전용 HTTPS로 밖에서 접속할 때만 기존 Tailscale 연결이 필요하다. 사용자가 꺼둔 네트워크를 자동으로 복구하거나 새 로그인하지 않는다.
배포의 LocalOnly는 정확한 기존 실행 세대·PID·원장 유휴·정상 중지 ACK를 확인한 다음 같은 loopback 포트로 한 번 시작한다. 원격 origin, Tailscale 설정과 공개 범위는 변경하지 않는다. 기존 모니터 정상 종료 후 새 모니터를 단회 활성화하고 완료 영수증으로만 이후 부팅을 허가한다. 불명 작업은 재발신하지 않고 복구본·원 요청을 보존한다. 포트가 같으므로 사용자가 나중에 기존 Tailscale을 켜도 기존 경로의 포트를 바꿀 필요가 없다.

## 계정별 한도 사전 차단

명시적 로컬 정책 적용 시 번호가 확인된 1번 계정은 기존 한도 기준과 자동전환을 유지하고, 나머지 번호 계정은 사전 차단을 끈다. 계정 선택 → 관리 → 한도 사전 차단에서 각 계정을 켜거나 끈다. 공통 사용률 기준·중지/전환 동작은 기존 자동 전환 화면을 사용한다. 정책이 없거나 번호가 모호하면 기존 보호를 유지한다.

이 설정은 AICC의 사용률 기준 사전 차단만 조정한다. 공급자가 실제 반환한 한도 거절, 인증·최신 사용량 확인·응답 불명 및 계정별 대화 보호는 유지한다. 실제 한도 회복 후 원 대화 자동재개는 별도 기능이다. 변경은 신원 결속·단회 preview/commit·로컬 원본 보존·실행 중 API 재조회로 확인하며 불명 결과는 읽기 전용으로 조정한다.
