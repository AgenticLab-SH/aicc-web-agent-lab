# 트레이의 PC·휴대폰 웹 화면

트레이와 웹은 같은 계정 제어 실행기·정책·경고 설정·결과 원장을 사용한다. 웹 구현은 `src/mobile-control.mjs`, `src/mobile-tray-tools.mjs`, `src/ocx-quota-dashboard.mjs`, `src/ocx-quota-slack-monitor.mjs`와 `public/mobile*`에 둔다. 개인 주소·계정·원 요청·배포 영수증은 Git에 넣지 않고 소유자 운영 기록에 보관한다.

## 화면 구성

- **계정·한도**: 전체 계정의 두 창 사용량·남은 비율·초기화 시각·현재 선택·중지·차단 상태. 계정별 조작은 펼치기. 계정 순서 변경은 전체 도구에서 제공한다.
- **트레이 도구**: 현재 트레이의 명명된 기능 전체 목록과 검색. 웹 화면 연결, PC 실행기 요청, PC 직접 사용 필요 상태를 구분한다. RDC 저장·선택·자동 순환·중지·원 결과 조정, 초기화권 조회·사용, 문제해결·준비된 복구·진단·관리 화면 열기를 기존 실행기에 연결한다.
- **작업·대화**: 선택한 기존 대화 큐의 등록·켜기·끄기·보류 해제·추적 종료. 큐 등록과 실제 메시지 전달·새 turn·전체 업무 완료는 별개다.
- **웹 감독기**: 기존 등록 대화·감시·재개 조건·대화 간 전달 승인 설정.
- **목표 원장**: 기존 원장의 읽기 전용 projection. 원장 생성 시각과 관측 시각을 구분한다. 새 원장을 만들거나 목표·내장 goal을 임의 완료 처리하지 않는다.
- **설정·연결**: 브라우저의 글자 크기·사용/남은 비율 표시·갱신 간격, 기존 영구 기기 인증, 기기 철회와 도움말.

## 실제 지원 경계

명명된 실행만 허용하고 임의 명령·경로를 받지 않는다. PC 창 열기는 PC 실행 요청 접수이며 폰에 PC 창을 보여주거나 실제 표시를 확인한 결과가 아니다. 로그인·터미널의 로컬 폴더 선택·PC 창 고정/투명 배경·트레이 종료는 기존 원격 IPC/정상 종료 계약이 없는 경우 PC 전용으로 이유를 표시한다. PC 트레이가 실행 중 읽지 않는 설정을 파일에 저장한 것만으로 즉시 반영됐다고 표시하지 않는다. 브라우저 표시 설정은 이 브라우저에만 저장한다. Desktop 큐의 무인 메시지 전달도 기존 실행기 지원 범위를 넘겨 보장하지 않는다.

변경은 신선한 상태와 정확 신원, 미리보기·단회 확인·단일 작성·durable 결과 원장을 사용한다. 읽기 실패는 변경 결과 불명과 구분한다. 변경 결과 불명은 원 요청을 조정하며 다시 실행하지 않는다. 초기화권은 기존 권한·정확 계정·실제 사용 가능 근거와 원 실행기를 유지한다.

## 모바일 스크롤

한 번에 하나의 관리 탭을 표시하고 페이지를 기본 세로 스크롤로 사용한다. 계정 카드의 조작을 접고, 큰 목록·카드에 고정 높이 세로 스크롤을 만들지 않는다. 오류는 해당 영역에 표시하며 화면 아래에서 다른 조작을 덮지 않는다. 결과·로그의 긴 줄은 명시된 가로 스크롤을 사용한다. 확인 대화상자만 배경과 분리된 스크롤이며 실행/취소 버튼을 계속 표시한다. 키보드 포커스·비활성 이유·좁은 화면 줄바꿈을 코드에 포함하되 실제 화면 측정을 했다고 간주하지 않는다.

## 설치와 복구

`tools/platform/windows/Install-AiccMobileQuota.ps1`은 고정 배포본을 준비하고 기존 비공개 HTTPS 경로와 자동 시작 작업을 CAS로 갱신한다. 새 서버 대기 기동 → 경로 전환 → 이전 서버 정상 종료 → 감시 단회 활성화로 중복 알림 감시를 피한다. 원본 Task·프록시·실행기·manifest·설정의 복구점을 남긴다. 기기 신뢰 저장소와 계정·모델 경로는 보존한다. 불명 단계는 원 operation을 Reconcile하며 재기동/변경 재발신으로 대체하지 않는다.

## 적용 상태의 해석

소스 작성·고정 배포·기동 ACK·주소 전환·실제 PC/폰 조작·Slack 수신을 별도로 기록한다. 코드 변경 후 테스트·빌드·브라우저·폰 조작과 Slack 수신 검증은 미실행이다. 기능 목록에 표시된다는 사실만으로 모든 PC 전용 기능이 원격 실행 가능하다는 뜻은 아니다.

## 연결 유지
- 직접 loopback 주소의 PC 소유자 세션은 시간 제한이 없다. 서비스가 다시 시작되면 기존 same-origin/loopback 계약으로 새 세션을 자동 발급한다.
- 비공개 HTTPS 주소는 같은 PC에서 열어도 remote 요청이다. 최초 한 번 계속 허용으로 등록한 브라우저는 서버 시간 제한 없이 직접 철회 전까지 유지한다. 서버에는 비밀 해시만 저장하며 기존 origin별 신뢰 저장소를 보존한다.
- 등록 링크 자체는 2분 단회이다. 등록된 연결의 무기한 유지와 별개다. 열린 탭에 같은 링크의 fragment만 바뀌어도 정상 최초 교환을 수행하도록 로드한다.
- 쿠키는 사용 시 갱신한다. 브라우저의 저장 상한·쿠키 삭제·시크릿 모드는 앱에서 무제한 보존을 강제할 수 없으며 해당 경우에만 재등록한다. 미등록을 무조건 만료로 표시하지 않는다.
- Chrome과 Codex 내장 브라우저는 별도 기기로 등록한다. 기존 휴대폰 기기를 지우거나 다른 브라우저의 인증을 복제하지 않는다.
- 이번 소스 변경 후 검증 미실행. 변경 전 실제 두 브라우저의 기존 계속 허용 등록을 수행한 결과와 구분한다.
## 서비스 교체·여러 탭에서 연결 이어가기
- 변경 요청 전 same-origin 세션 조회로 CSRF 확인값을 갱신한다. 계속 허용 기기는 기존 신뢰 저장소를 사용하며 새 등록을 요구하지 않는다. 직접 loopback 세션만 기존 로컬 발급 계약으로 복구한다.
- 세션 확인값이 바뀌면 이전 미리보기를 해제한다. 단회 실행 확인은 재전송하지 않는다. 정확한 csrf_required/409/automaticReplay=false 거절은 실행 전 거절이므로 사용량 조회·미리보기만 새 확인값으로 한 번 재시도한다. 연결 단절·응답 파싱 실패·일반 오류는 재전송하지 않는다.
- 네트워크 복귀·탭 재표시 때 연결 정보만 갱신한다. 이 동작은 계정 변경·초기화권 사용·명령 발신을 하지 않는다.
- 브라우저 저장소를 사용할 수 없어도 현재 페이지의 원 operation ID를 보존한다. 화면 초기화 오류와 인증 실패를 구분한다.
- 계정·차단 정책·경고 편집의 미저장 상태를 분리하고 자동 조회로 입력한 우선순위를 지우지 않는다. 적용한 종류의 제출 값과 현재 입력이 같을 때만 미저장 표시를 해제한다. 화면 타이머 종료 중 완료된 조회가 타이머를 다시 만들지 않는다.
- 구현·서비스 적용과 실제 조작 성공은 구분한다. 이 변경 후 검증 미실행.
## 브라우저 새로고침 지연 분리
- 모듈 초기화에서 전체 계정·서비스 진단 완료를 기다리지 않는다. 연결 확인 뒤 선택한 탭을 먼저 열고 해당 탭만 조회한다. 계정 외 설정 탭도 계정 조회 완료를 기다리지 않는다.
- 인증된 GET quota?view=accounts는 설치된 collector의 기존 onAccounts projection을 먼저 사용한다. 불완전한 진단은 진행 중으로 표시하며 선택 검증 완료로 취급하지 않는다. 전체 collection은 하나로 유지하고 기존 Slack/전체 read/preview·변경 안전 검사는 원래 계약을 따른다. 완료 결과는 선행 화면 조회에만 최대5초 재사용한다.
- 화면은 최대10회의 짧은 후속 조회로 전체 결과를 받아온다. GET의 응답 대기는 세션8초/일반15초로 제한하며 서버 작업을 취소하거나 변경 요청을 재전송하지 않는다. 화면·메뉴·기존 관측값은 유지하고 지연 상태를 표시한다.
- 화면 의존 모듈은 미리 함께 내려받는다. 실제 폰에서 Tailscale 접속/네트워크가 느린 경우까지 코드 변경만으로 해결됐다고 간주하지 않는다. 변경 후 검증 미실행.
## 트레이 종료 상태에서 사용하기
- AICC 상태 트레이와 전체 AICC Workspace를 켜지 않아도 독립 모바일 관리 실행기와 OCX가 켜져 있으면 계정·한도 조회, 사용/일시중지/재개, 우선순위·순서·정책·경고 설정을 요청할 수 있다. 초기화권은 기존 소유자의 정확한 계정·단회 실행 계약을 그대로 사용한다.
- 일반 계정/Slack 주기 조회는 Workspace 상태용 별도 프로세스나 CDP를 호출하지 않는다. 전체 서비스 진단은 도구에서 명시적으로 요청한다. OCX도 종료하면 실시간 계정 관리가 불가능하며, PC 절전/종료 때는 계속 알림을 보장하지 않는다.
- 초기화 시각은 사용률과 같은 OCX 관측의 timestamp를 전달한다. 외부 OCX를 쓸 때 오래된 legacy 디스크 캐시는 초기화 시각 근거로 사용하지 않는다. 제공되지 않은 시각은 그 사유를 표시하고 추정하지 않는다.
- 계정 상단 바로가기와 각 계정 초기화권 버튼은 기존 기능으로 이동한다. 사용률/잔여율, KST 초기화 시각과 남은 시간은 두 기간을 나란히 비교한다. 검색·상태 필터·정렬을 지원한다.
- 도구 목록은 웹에서 사용하는 기능, PC 창 열기 요청, PC에서 직접 사용하는 기능을 구분한다. PC 창은 휴대폰 내부 화면이 아니다. GUI 고정·글래스·종료, 새 로그인, 정확한 복구 준비처럼 별도 PC 계약이 필요한 항목은 안내를 유지한다.
- 이번 수정 후 테스트·빌드·브라우저·실행 검증 미실행. 고정 배포·정상 교체 ACK와 실제 동작 인수는 구분한다.
## Tailscale을 끈 PC 로컬 적용
PC의 loopback 주소 사용과 화면 배포에는 Tailscale이 필요하지 않다. 기존 전용 HTTPS로 밖에서 접속할 때만 기존 Tailscale 연결이 필요하다. 사용자가 꺼둔 네트워크를 자동으로 복구하거나 새 로그인하지 않는다.
배포의 LocalOnly는 정확한 기존 실행 세대·PID·원장 유휴·정상 중지 ACK를 확인한 다음 같은 loopback 포트로 한 번 시작한다. 원격 origin, Tailscale 설정과 공개 범위는 변경하지 않는다. 기존 모니터 정상 종료 후 새 모니터를 단회 활성화하고 완료 영수증으로만 이후 부팅을 허가한다. 불명 작업은 재발신하지 않고 복구본·원 요청을 보존한다. 포트가 같으므로 사용자가 나중에 기존 Tailscale을 켜도 기존 경로의 포트를 바꿀 필요가 없다.
이번 구현 후 검증 미실행. 로컬 배포 ACK와 브라우저 실제 사용은 구분한다.
## 로컬 진입 주소와 중단된 실행기

PC의 기본 `localUrl`과 `privateLocalUrl`은 현재 적용된 계정 관리 화면을 가리킨다. 이전 public 화면을 보존하더라도 기본 진입점으로 남기지 않는다. 배포기는 알려진 loopback mobile.html 진입 주소만 새 포트에 맞추고 외부 origin·사용자 지정 경로·기기 신뢰는 보존한다.

예약 작업의 Running이나 과거 LISTENING 기록만으로 현재 웹 실행을 판단하지 않는다. 기록의 PID·시작 시각·실행 경로와 현재 listener를 함께 대조한다. PID가 재사용될 수 있으므로 숫자만으로 같은 실행 세대라고 판단하지 않는다. 최신 listener가 없으면 기존 실행기·감시 소유·진행/불명 원장을 먼저 조정한다. 완료 영수증의 restart authorization과 등록된 숨김 launcher를 재사용하며, 원 Apply·모바일 변경·Slack 전송은 재발신하지 않는다. 살아 있는 구형 listener의 불명 작업은 종료하지 않는다.

소스 수정은 미래 배포에 적용된다. 이미 고정된 release·launcher·restart authorization은 직접 수정하지 않는다. 적용과 사용 확인 여부는 소유자의 현재 운영 기록에 별도로 남긴다.
